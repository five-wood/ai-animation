# ladingwu 关键帧版：生成与实机验证报告（2026-11-12）

- **输入**：
  - 美术审核过的 `keyframes_artist.json`（lin，r1，`reviewed=true`）：34 个结构键，保留了全部候选，没有删改，也没有采纳过渡键。从服务器取回后，核对过它基于的候选文件和本地 `work/maxkeys/m11101_tex_ladingwu/keyframes_auto.json` 哈希一致。
  - 动作、读数、着地判断用的是同一个本地副本：`motion_temporal.npz`、`reading.npz`、`contacts_auto.json`。
- **生成**：[build_keyframe_edit.py](../../video2rig/tools/max2026/build_keyframe_edit.py)（新增，只依赖系统 Python 和 NumPy）。输出的数据包格式和 spline 版相同，所以写入、评估、检查、叠骨架对照沿用原有脚本：`import_spline_edit.py`、`evaluate_spline_edit.py`、`post_checks_spline.py`、`overlay_video.py`。这两个脚本加了一个环境变量 `V2R_OUT_NAME`，用来指定输出文件名，默认值保持不变。
- **写入**：用 `3dsmaxbatch` 打开 [base_scene.max](../max_editable_20261109/base_scene.max)，无界面写入后另存。美术正在用的两个 Max 窗口没有受影响。原始角色文件 SHA256 是 `2476096d…`，base 是 `81da510e…`，都没有变化。

## 核心改动（相对 11-11 spline 版）

| | spline 版（美术退回） | 关键帧版 |
|---|---|---|
| 键的时间 | 按部位挑键，按误差补过渡键，共 177 帧有键 | 全身共用美术审核的 34 帧 |
| 键的姿势 | 合法化后的逐帧动作 | 同样合法化；接触、停顿、起止取去抖后的姿势，极值、发力点、转圈段取原帧 |
| 着地段 | 合并后的 contacts_plan，左脚 0–130 帧被当作一段连续着地 | 美术确认的接触键对应的着地段（`contacts_auto.json` 中 ≥ 6 帧的段），左 4 段、右 5 段 |
| 落脚点 | 尽量放在视频读到的落脚点，代价是身体下沉，最多 5.1cm | 先保证身体高度离视频不超过 1.5cm，再让脚尽量接近视频落脚点 |
| 身体高度 | 只往下压，保证膝盖至少弯 15° | 着地腿的膝盖保持在 20–35°（自然站姿带），身体可以上下调，以离视频最近为准；插值帧上膝盖不会伸直 |

## 调参过程（每一版都在 Max 里实际写入并逐帧采样）

| 版本 | 改了什么 | Max 实测发现的问题 |
|---|---|---|
| draft0 | 身体只往下压，脚尽量往视频落脚点拉 | 离线数据就显示：要把脚放到视频落脚点，身体得下沉 4–7cm（和旧版一样“蹲马步”）。原因是视频落脚点离髋水平 8–22cm，腿只有 14.5cm |
| v1 | 改成“站姿带”：身体可升可降，脚取够得着的最近点 | 离地的脚在插值时最多穿地 2.3cm（free 键贴着地面，身体转动时脚跟着身体空间插值往下掉）；膝盖在键之间偶尔伸直 |
| v2 | 离地键抬高 1–6cm；插值帧最低膝盖角放宽到 8° | 膝盖仍有几帧伸直（0.2°）。原因是在键与键之间，Biped 让着地脚踝滑了 0.3–0.4cm，而腿短，0.2cm 就相当于约 10° 的膝盖角 |
| v3 | 着地膝盖最小角提到 20° | 膝盖问题解决；右脚落地前 5 帧，脚尖穿地 2.3cm（从远处的离地键插值进来时掠过地面） |
| **v4（交付）** | 落地前 2 帧、离地后 2 帧，在落脚点上方 2cm 各加一个 free 键 | 不再穿地，膝盖 12–77° |
| v4_bd16 | v4 加上阶梯前 16 个建议过渡键（对照版） | 右脚第 133 帧附近脚尖进地 0.8cm，这里新加了过渡键，没有落地前的悬停键 |

## 结果

### 键数

- 主版本：34 个全身键。所有身体骨骼都只在这 34 帧上有键（`import_report.json` 的 inventory 里核对过）。
- 脚 IK：左 47 个键（4 段着地），右 50 个键（5 段着地），包括 planted 保持键、离地键和落地前/离地后的悬停键。
- 对照版：50 个全身键；脚 IK 左 61 个、右 63 个。

### 写入精度（关键帧上，Max 与目标姿势的差，cm）

COM 0.000、躯干 0.010、左臂 0.029、右臂 0.151、耳朵 0.010、尾巴 0.000。

### Max 逐帧采样与视频拟合对比（cm，已扣除身体高度调整）

| 部位 | max | p95 |
|---|---|---|
| COM / 躯干 | 16.6 | 3.5 |
| 左臂 | 25.1 | 6.7 |
| 右臂 | 29.9 | 6.9 |
| 耳朵 | 18.4 | 4.9 |
| 尾巴 | 5.4 | 2.2 |
| 脚 | 13.3 | 10.7（主动调整落脚点造成，见下文） |

**分段看（p95）**：
- 非转圈段：身体 2.3、左臂 6.7、右臂 5.6；
- 转圈段（Max 第 181–213 帧）：左臂 15.6、右臂 14.5。

**最大偏差都在转圈段**：
- 第 180–188 帧：21cm，手在两个技术键之间的走法跟不上；
- 第 206–211 帧：19cm。

**非转圈段最大偏差**：第 99–119 帧的长间隔，约 10.6cm，偏差在手上。

**对照版（加 16 个过渡键）** 非转圈段 p95：身体 0.7、左臂 3.3、右臂 2.2，和旧版 spline（0.7 / 3.3 / 2.6）相当，但身体只用了 50 帧有键（旧版 177 帧）。

### 脚与膝盖

| | 左 | 右 |
|---|---|---|
| 着地段内脚踝漂移最大 | 0.27cm | 0.00cm |
| 着地段内脚转动最大 | 2.0° | 0.0° |
| 着地膝盖弯曲 | 14–71° | 12–77° |
| 脚趾最低点 | 0.20cm | 0.22cm（不穿地） |

- **身体高度**：比视频最多低 1.56cm、最多高 1.08cm，平均差 0.94cm（旧版只下沉，最多 5.07cm，平均 1.84cm）。
- **落脚点**：6 段着地的落脚点比视频读数偏 8–19cm（明细见验收说明）。这是第一节表格里“落脚点”一行的取舍带来的：腿只有 14.5cm，把脚放到读到的位置就得深蹲或者够不着。
  - 另外，读数可能落在脚尖或鞋面上，`Bip001 Foot` 关键点是脚踝，这一点还没有核实。

### 编辑测试与受保护曲线（[post_checks.json](v4/post_checks.json)）

- 在双脚都着地的第 148 帧，把重心键下移 1.5cm，只改这一个键：着地脚漂移前后都是 0.27cm 和 0.00cm，右膝最大弯曲从 77° 变成 91°。结果另存为 [com_edit_test.max](v4/com_edit_test.max)。
- 675 条已有曲线中，只有 `Dumm_input` 的缩放键有约 1e-5 的显示差异，和之前几版相同。

## 问题标记（key_poses.json 的 `flags`）

- 左肘伸到极限：8 个键；右肘：1 个键（第 0 帧）。
- 手的读数置信度低于 0.5：左手 15 个键，右手 5 个键。
- 快速转圈段：8 个技术键。
- 着地点偏 > 5cm：6 段，在每段的第一个键上标出。
- 离地键为了贴地或够得着，比读数挪了 3–4.5cm：3 处。

## 已知限制

1. **长间隔的插值走样**：
   - 第 99–119 帧最大约 10cm；
   - 开头第 0–14 帧约 6cm。
   - 加过渡键能解决；用不用、加在哪里，由美术决定。
2. **转圈段**：技术键的间隔已经只有 2–4 帧，手臂仍然跟不上，偏差约 15–21cm。这一段需要人工处理，或者另想办法（例如手臂相对身体单独打键）。
3. **插值近似和 Max 的差别**：离线计算用的是 Catmull-Rom，和 Max 的 TCB 0/0/0 实测一致（COM 位置差 0.00cm）。但 Biped 在键之间会让着地脚踝滑 0.3–0.4cm，所以着地膝盖的最小角设为 20°。
4. **着地判断**：仍然沿用 `contacts_auto.json` 的自动结果。美术审核的是关键帧的时间点，并没有确认各段着地的起止区间。
5. **只验证了这一段 clip、这一个角色**：骨架配置 bind profile 只有 m11101 这一副。
