# ladingwu 关键帧版：美术验收说明（2026-11-12）

## 打开方式

在 Max 里选 **Scripting → Run Script**，运行 `D:\Project\ai-animation\video2rig\tools\max2026\V2R_Max2026.ms`，弹出窗口后点按钮：

| 按钮 | 文件 | 说明 |
|---|---|---|
| **Open ladingwu KEYFRAME edit** | [v4/keyframe_edit.max](v4/keyframe_edit.max) | 主版本：只在你审核过的 34 个关键帧上打全身键 |
| Open … + 16 breakdowns | [v4_bd16/keyframe_edit_bd16.max](v4_bd16/keyframe_edit_bd16.max) | 对照版：在 34 个关键帧基础上，按网页建议补了 16 个过渡键，共 50 个 |
| Open 2026-11-11 ladingwu spline edit | 旧版 | 上次被退回的版本，177 帧有键，留作对比 |

两个新文件都是原角色副本，原始角色文件没有改动（SHA256 核对过）。播放范围是 0–240 帧（30fps）。**改完请另存新文件名。**

## 这一版的做法

- **键的时间**：完全采用你在网页上审核的 34 个关键帧（lin，r1）。视频帧换算到 Max 帧的公式是 `Max 帧 = round(视频帧 × 30/24)`。
- **全身共用这 34 帧**：躯干、手臂、耳朵、尾巴、重心都在同样的帧上有键，没有其他身体键。
- **键的姿势**：每个键都是 Biped 能做出来的姿势，规则和上次一样：肘只能单向弯、锁骨的约束、骨盆跟随重心。
  - 接触、停顿、起止这类键：取前后约 1 帧的平均，去掉读取抖动。
  - 极值、发力点和转圈段的键：直接用原帧，动作顶点不会被削平。
- **腿**：不打键，由 Biped IK 根据脚的位置和重心计算。
- **脚**：
  - 着地段按你确认的接触键来分。每段的开头是 sliding 键，之后是 planted 键，并在段内每个关键帧加一个 planted 保持键。
  - 离地时，在每个关键帧打一个 free 键，脚抬离地面约 2cm。另外在落地前 2 帧和离地后 2 帧，各加一个“悬在落脚点上方”的键，防止抬脚时插值穿进地面。
- **站姿**：着地的腿保持自然弯曲（约 14–77°），身体高度与视频的差控制在 1.6cm 以内。

怎么看这张表：

- 关键帧版的偏差是“只给关键姿势、其余交给 Max 插值”的结果。偏差主要出现在长间隔里，例如第 99–119 帧之间手的走法和视频差约 10cm。如果你觉得节奏或弧线不对，有两种改法：
  1. 自己在 Max 里补一个键；
  2. 回网页上把“过渡键数量”滑杆往右拖，采纳几个过渡键后保存，我再重新生成。
- 加上 16 个过渡键后，非转圈段的偏差回到和旧版差不多（身体 0.7cm），但键数只有旧版的 28%。
- **转圈段（第 181–213 帧）**：每 2–4 帧就有一个技术键，但手臂一帧要动 20cm 以上，插值跟不上，最大偏差约 21cm。这一段需要你手动处理，或者告诉我希望怎么处理。

## 需要你特别看的地方

**着地点的取舍**：

角色腿很短，大腿加小腿只有 14.5cm。视频读出的落脚点有 6 处离身体太远：如果脚真放在那里，要么把身体压低 4–7cm，要么腿伸不到。这一版选择让身体基本保持视频高度，把脚收到腿够得着的位置，因此下面这些着地点比视频偏了 8–19cm，主要是向身体内侧收。

| Max 帧 | 脚 | 比视频偏 |
|---|---|---|
| 18–29 | 右 | 8cm |
| 35–54 | 右 | 13cm |
| 90–99 | 右 | 11cm |

| 141–154 | 左 | 19cm |
| 215–240 | 左 | 18cm（最后的结束姿势，左脚踢在外侧） |

如果你更希望脚踩准、身体低一些，告诉我，可以换成另一种取舍。参数 `--height-cap` 控制身体最多可以比视频低多少。

**手臂**：
- 左肘有 8 个键伸到了极限（伸直）。原因是视频里左肘弯向了 Biped 转不过去的方向，或者是读取错误。

## 已经实测过的修改操作

- **把一个重心键下移 1.5cm**（第 148 帧，双脚都着地）：着地脚完全没动，漂移前后都是 0.27cm；只有膝盖弯得更多。结果另存为 [v4/com_edit_test.max](v4/com_edit_test.max)。
- **原场景其他曲线**：675 条已有曲线中，只有 `Dumm_input` 的缩放键有约 1e-5 的显示差异，和前几版相同，是浮点显示造成的。
