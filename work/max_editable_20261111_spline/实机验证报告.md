# 2026-11-11 spline 可编辑版：实机验证报告

- **对象**：m11101 原角色（Biped + Bone），源为 [motion_temporal.npz](../maxkeys/m11101/motion_temporal.npz)，24fps、121 帧、5 秒。
- **目标**：3ds Max 2026.2，30fps，0–150 帧。
- **执行方式**：`3dsmaxbatch.exe` 无界面运行，每次从 [base_scene.max](../max_editable_20261109/base_scene.max) 开始，只另存新文件。
- **文件保护**：原始场景 SHA256 仍为 `2476096d…2378`；`base_scene.max` 的 hash 不变；11 月 9 日的输出没有被改动。

## 流程

```text
源拟合关键点 + 源 FK
  → build_spline_edit.py：Biped 合法化 + 分部位排键（离线）
  → import_spline_edit.py：Max 写键（姿势键 + 过渡键 + 双脚 planted IK）
  → Max 回采：整数帧 + 半帧，共 301 个时刻
  → evaluate_spline_edit.py / post_checks_spline.py：误差、受保护曲线、COM 编辑测试
```

## Biped 合法化模型

以下规则在 11 月 9 日的 Max 采样中逐条核实过：

| 规则 | Max 实测依据 |
|---|---|
| Pelvis 位置等于 COM，骨盆运动由 COM 承担 | Pelvis 在 COM 坐标系下位置差 0 |
| Clavicle 头部固定在 Spine1 上（不是 Neck） | 在 Spine1 坐标系下位置差 0；在 Neck 坐标系下差 1.56cm |
| Clavicle 相对 Spine1 不能绕骨轴扭转 | Max 中扭转范围在 ±1° 以内；源数据有 −8.6° 到 9.5° 的扭转 |
| UpperArm、Forearm、Hand 的头部在父骨 +X 轴上，长度固定 | 父骨坐标系下偏移为 `[20.699, 0, 0]` / `[15.684, 0, 0]` |
| Forearm = UpperArm · Rz(θ)，θ ≤ 0 | Max 中偏离 Z 轴的量为 0，θ 范围 −66° 到 0 |

- **手臂求解**：每帧用最小二乘拟合锁骨摆动（2 个参数）、上臂旋转（3 个）和肘角（1 个，限制在 −145° 到 0），使 8 个手臂关键点贴合观测，手部保持源的世界旋转。
- **双脚**：每只脚定一个世界锚点，xy 取源数据的中位数，高度和朝向取参考姿势（偏航用源数据的中位数）。整体下沉 0.67cm，保证锁脚后膝盖至少弯 15°。

## 结果

### 键数

所有键都在整数帧上，每两个姿势键之间 1–3 个过渡键，没有部位超过容差。

| 部位 | 姿势键 + 过渡键 | Max 中实际存储的键数 |
|---|---|---|
| COM | 4 + 6 | 垂直、水平、转向各 10 |
| 躯干/头 | 9 + 8 | 每个节点 17 |
| 左臂 | 10 + 13 | 每个节点 23 |
| 右臂 | 14 + 21 | 每个节点 35 |
| 左耳 / 右耳 / 尾巴 | 3+3 / 6+6 / 7+6 | 6 / 12 / 13 |
| 双脚 IK | 每只脚 2 个（第 0 帧 sliding、第 150 帧 planted） | Thigh、Calf、Foot、Toe0 各 2 |

- 共 120 个部位键，涉及 67 个不同的帧时间。
- 对比：11 月 9 日的稀疏版是全身共享 70 个时间，其中 52 个不在整数帧上；满帧版是 121 个时间。

### 误差

关键点误差，单位 cm，Max 实际求值，统计整数帧：

| 部位 | Max 相对合法化目标（稀疏化 + 写入误差）max / p95 | Max 相对原拟合（总偏差，已扣除整体下沉）max / p95 |
|---|---|---|
| COM/躯干 | 1.11 / 0.44 | 1.11 / 0.44 |
| 左臂 | 1.63 / 0.98 | 1.82 / 1.38 |
| 右臂 | 1.51 / 0.77 | 1.70 / 1.10 |
| 耳朵 | 1.53 / 0.97 | 1.53 / 0.97 |
| 尾巴 | 0.60 / 0.45 | 0.60 / 0.45 |
| 脚 | 0.00 / 0.00 | 2.39 / 1.80（主动锁脚造成的有意修正） |

- **对照**：11 月 9 日的满帧原生重定向，左肘偏差 4.58cm、左上臂偏差 41.7°。
- **合法化本身带来的偏差**（离线计算）：
  - 手臂拟合残差 max 1.66 / 1.74cm；肘部位置变化 1.48 / 0.98cm；手腕变化 0.29 / 0.20cm；肩部位置移动 0.70 / 0.95cm。
  - 左肘 151 帧全部停在铰链极限 0°，也就是伸直。源数据中左肘有 144 帧是向 Biped 铰链不允许的方向弯曲。
- **写入保真**：键帧时刻的局部值与目标一致，躯干、耳朵、尾巴的旋转误差在 0.002° 以内。锁骨在键帧上有 0.3–1.7° 的偏差，方向基本是绕骨轴扭转。判断是 Biped 写入锁骨时强制去掉了扭转，模型里锁骨扭转的参考坐标系与 Biped 内部的定义还差一点，待修。

### 脚与编辑测试

- 双脚相对锚点：301 个时刻里位置漂移最大 0.0003mm，朝向偏差 0.04°以内。
- 膝盖弯曲：左 30–58°，右 12–46°。右膝在两个键之间因 COM 插值，最小只有 12.5°，没达到 15° 的设定。
- 脚趾高度稳定在 0.54cm，与参考姿势一致。
- **COM 单键编辑**：只改第 90 帧 COM 一个键，下移 1.5cm，其他键不动。双脚漂移仍在 0.0004mm 以内，膝盖分别弯到 71° / 56°。结果另存为 [com_edit_test.max](com_edit_test.max)。

### 受保护曲线

675 条非 Biped、非本次写入的曲线全部保持不变。

- 首轮检查曾报告 `Dumm_input` 链接约束的缩放在第 0 帧有约 1e-5 的差异。
- 随后用 [probe_track_diff.py](../../video2rig/tools/max2026/probe_track_diff.py) 逐键对比，两个文件存储的键值和属性完全一致（见 [track_diff_probe.json](track_diff_probe.json)）。
- 结论：差异来自不同会话中求值 `c.value` 时的浮点显示，不是曲线被修改。

## 已知限制与后续

1. **锁骨扭转写入偏差（0.3–1.7°）**：需要先在 Max 里测出 Biped 锁骨扭转的参考坐标系，再修正合法化模型。
2. **左肘全程伸直**：这是源数据加 Biped 铰链共同决定的。可能是视频里本来就是直臂，也可能是 reader 的肘部方向读错了，需要看视频确认。
3. **锁脚是人为判断**：本片段被当作全程双脚支撑，没有自动接触判定。换步、单脚、跳跃都还没做。
4. **小腿可观测性没有修**：现在腿型完全由 Biped IK 决定，没有用源数据的膝盖信息（源里本来也没有可靠的膝盖信息）。
5. **插值是近似计算的**：离线排键时用 Catmull-Rom 近似 Biped 的 TCB 插值。Max 实测和离线估计一致（max 1.5–1.6cm），但两者不保证完全等价。
6. **工具还不能直接给美术用**：路径、角色、片段都是写死的；`import_spline_edit.py` 拒绝覆盖已有输出，重跑需要先归档旧输出。旧的第一版放在 [v1/](v1/)，那一版右臂有 4 段超出容差。
7. **美术实际操作验收还没做**：见 [美术测试说明](美术测试说明.md)。
