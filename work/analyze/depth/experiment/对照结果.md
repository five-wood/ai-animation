# 已有专用关节深度：关闭/数值/顺序对照

2026-11-03。不是部署 Depth Anything；使用现有reader的相对关节深度头。没有重训、没有改变默认、检查阈值或原视频。

## 方法

每case使用完全相同UV、conf_fit、X_fit、depth、fps和同一新生成的depth-OFF warm start（legacy900迭代，非GT初始化）。后续temporal850步+LBFGS预算一致，仅改变depth term。

- off：关闭最终深度约束。
- numeric：现有相对深度MSE，strength=.025。
- order：rig互反mirror pair，使用预测深度差符号，hinge-square；预设min_gap=.02体型、min_weight=.2、0.2秒窗≥80%同符号且≥60%支持；margin=min(|gap|*.5,.03)。不是可见性/正确率保证。
- 另做strength .25/2.5（10x/100x）敏感性，非默认。
- order只约束深度顺序，不改变2D identity；不能用其内部排序达标证明语义正确。

## 独立审计结论

详见../depth_report.md。reader整体8pair顺序约91.9%，脚踝约87.3%；较大预测gap可提高保留样本准确率但降低覆盖率。真正遮挡脚踝样本很少，某阈值只2/4正确，不能作硬先验。
现存legacy UV swap未同步depth；temporal已同步且产物验证。还有整链UV修正与depth身份冲突的实例（frame30 side），不能把head输出当互相独立真值或自动硬交换依据。

## 结论

这轮没有证明深度辅助可修复左后腿，故不推广为默认，也不添加声称有效的网页开关。不靠持续加大权重追求可见变化。
接下来更应保留热图多候选并联合身份/几何决策、明确不可见状态和多解，而不是让一个错误点附带的深度决定正确姿态。通用单目表面深度无法直接给出被身体挡住的骨骼关节深度。
