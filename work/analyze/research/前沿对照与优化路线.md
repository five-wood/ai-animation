# 视频还原动画：前沿研究对照与优化路线

整理时间：2026-11-04。对象：`video2rig`（m11101 兔子为主要样例）。
外部资料是检索结果，部分细节来自二手整理页面，已在文中注明；实施前以论文 / 代码原文为准。

---

## 一、当前方案

两机位同框参考图 → Seedance 生成两机位视频 → 每只怪物专属 DINOv2 识别器（热图 + 相对深度，48 个关键点）
→ 左右交换修正 → 三角测量 → 一致性检查 → 关节限制内拟合骨骼（legacy / temporal 两种求解器）→ 导出。

2026-11-03 的状态（m11101）：
- exam 通过：关节误差 1.45%，肢体方向 8.7°，扭转 7.4°（评分按骨骼真实长轴）。
- 真实视频 `Seedance25_Split_screen_two_loc_1793704727806`（121 帧，24fps）暴露的问题：
  - 手 / 手指抖动：静止时全身识别噪声中位 0.21px，但运动中手指偏离 5 帧中位轨迹 3~4px；两机位手部射线交汇误差 7.1px（身体 1.6px）。
  - 护目镜抖动：Bone146（护目镜所在骨骼）的识别点离骨骼起点很近，0.2px 的识别噪声被放大成 0~9.8° 的转动（头部本身只有 0.07°）。
  - 打击感：识别到的挥手急停约 2 帧，legacy 求解后 2~4 帧，temporal 求解后被拉长到 4 帧，峰值速度只剩 legacy 的 60~67%。
  - 枪：不跟手，5 个点和骨骼差 30~36px，可能拉偏左腿（左大腿误差 20.8°，右侧约 8°）。

## 二、前沿路线

| 路线 | 代表工作 | 做法 | 和我们的关系 |
|---|---|---|---|
| 多机位关节图 → 三角测量 → 反解骨骼 | [AnimaX](https://ar5iv.labs.arxiv.org/html/2506.19851v1)（SIGGRAPH Asia 2025） | 视频扩散模型同时生成四机位视频和关节图（每个关节一种颜色），聚类取中心得到 2D 关节 → 带骨长约束的三角测量 → 反解骨骼转角 | 重建段和我们几乎一样。区别：它让生成模型直接"画"出关节，我们用识别器"读"关节 |
| 可微渲染 + 稠密信号优化 | [Puppeteer](https://github.com/Seed3D/Puppeteer)（NeurIPS 2025） | 渲染蒙皮网格，与视频比对 RGB、剪影、关节点跟踪、表面顶点跟踪、光流、深度，加旋转平滑 / 加速度 / 父子连贯 / 根平滑正则，梯度优化每帧关节四元数 | 用整个表面的信号，我们只用稀疏点。据二手整理页 [zread](https://zread.ai/Seed3D/Puppeteer/13-multi-objective-loss-functions)：表面顶点重投影权重 3.0，高于关节点 1.5；可见性用射线与网格相交计数判断 |
| 可微渲染 + 物理二次运动 | [AnimaMimic](https://ar5iv.labs.arxiv.org/html/2512.14133)（CVPR 2026） | 单机位视频 + 自动绑骨（UniRig）+ 剪影 / 稠密点跟踪（AllTracker）/ 深度（VGGT）优化；再用可微软体模拟补惯性和弹性 | 指出纯蒙皮动画是"准静态"的，缺惯性。和打击感直接相关 |
| 分数蒸馏 | [AKD](https://openaccess.thecvf.com/content/CVPR2025/html/Li_Articulated_Kinematics_Distillation_from_Video_Diffusion_Models_CVPR_2025_paper.html)（CVPR 2025） | 用视频扩散模型做评委优化骨骼动作 | 一段约 25 小时，不适合生产 |
| 多机位一致视频生成 | [SynCamMaster](https://ar5iv.labs.arxiv.org/html/2412.07760)、[CAT4D](https://openaccess.thecvf.com/content/CVPR2025/html/Wu_CAT4D_Create_Anything_in_4D_with_Multi-View_Video_Diffusion_Models_CVPR_2025_paper.html) | 生成模型本身保证多机位同步 | 结构上消除"两半画了不同动作"，目前画质还不及 Seedance |

相关的单项技术：
- 体素融合三角测量：[Learnable Triangulation](https://ar5iv.labs.arxiv.org/html/1905.05754)，把各机位热图融合到 3D 空间再取峰。
- 稠密表面对应：[Continuous Surface Embeddings](https://ar5iv.labs.arxiv.org/html/2011.12438)，每个像素预测它在网格上的位置，已扩展到多种动物。
- 单视频测试时训练：[DINO-Tracker](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/03799.pdf)，DINO 特征 + 在单段视频上自训练。
- 点跟踪：[CoTracker3](https://openaccess.thecvf.com/content/ICCV2025/html/Karaev_CoTracker3_Simpler_and_Better_Point_Tracking_by_Pseudo-Labelling_Real_Videos_ICCV_2025_paper.html)。
- 速度自适应滤波：[1€ filter](https://dl.acm.org/doi/10.1145/2207676.2208639)，慢时强平滑、快时弱平滑以减少拖尾。
- 时序去抖网络：[SmoothNet](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136650615.pdf)（需要训练数据，暂不考虑）。

## 三、我们独有的条件

1. 两个标定好的固定机位（研究方法多数是单机位，深度靠猜）。
2. 首帧就是我们自己渲染的，像素 ↔ 网格点对应已知。
3. 纯色摄影棚背景，前景轮廓几乎可以直接抠。
4. 每只怪物一个专属识别器，训练数据可无限合成、自带精确标注（包括可见性、深度，以后还可以加表面坐标）。

**核心瓶颈**：只用了稀疏点。扭转、拳头朝向、护目镜、枪这类问题都属于"点看不出来、表面看得出来"。

## 四、优化点

### A. 不重训，利用已有条件

| # | 思路 | 解决 | 代价 / 风险 |
|---|---|---|---|
| A1 | 剪影约束：纯色背景抠前景，求解时让蒙皮网格剪影对齐 | 拳头朝向、体积、手臂扭转；几何上暴露枪的冲突 | 需要可微渲染库（pytorch3d / nvdiffrast），求解变慢；遮挡处有歧义 |
| A2 | 热图联合定位：在 3D 里找让两机位热图同时最高的位置，代替各自取峰再三角测量 | 手部多峰选错、手指乱跳 | 需保留热图；只对不确定的点做 |
| A3 | 速度自适应时序惩罚：小幅变化强平滑，大幅且双机位一致的变化放行 | 急停被拉长、打击感 | 只改求解器；需要急停考题量化 |
| A4 | 可观测性：按"识别点到骨骼起点的杠杆长度 / 识别噪声"估计转角误差，误差过大的骨骼求解时跟随父骨骼 | 护目镜及同类装饰骨骼 | 只在求解阶段生效；规则必须通用，不能写死骨骼名 |
| A5 | 手部整体约束：手和手指点按静止形状刚体拟合，偏离太远的点降权 | 手指乱跳 | 只改求解器 |

### B. 改识别器（合并一轮重训）

| # | 思路 | 解决 | 代价 |
|---|---|---|---|
| B1 | 稠密表面坐标头：每个前景像素输出它在静止网格上的 3D 坐标（Blender 多渲染一张坐标图即为标注）；求解用成千上万个像素↔网格对应 | 扭转、拳头朝向、护目镜、表面细节 | 改动最大；收益最大；先在 lizard 上验证 |
| B2 | 用上已有的可见性标注训练"是否被遮挡" | 被身体挡住的手仍给位置 | 小 |
| B3 | 枪按 `Weapon_R_slot` 挂到右手；拳头上少留手指点 | 枪不跟手、手指点混淆 | 小 |

### C. 针对当前视频的适配（探索）

| # | 思路 | 价值 |
|---|---|---|
| C1 | 测试时自训练：用两机位一致、高可信帧当伪标注，几分钟微调识别器后重读 | 缩小 Seedance 画面与渲染图的差距 |
| C2 | 点跟踪 + 识别器互补：首帧是自己渲染的，跟踪点的网格位置已知；跟踪管相邻帧（平滑、保急停），识别管绝对位置（不漂移） | 去抖同时保留打击感 |
| C3 | 物理二次运动：耳朵、围巾等加弹簧阻尼跟随 | 补惯性和跟随，增强打击感 |

### D. 视频来源

- 继续在提示词里要求首帧静止 0.5 秒、纯色背景、两画面同步。
- 关注多机位一致视频生成；可用后不必再一张图拼两机位。

### 已验证、不再投入

- 单机位深度：教程视频与本项目深度头对照（`work/analyze/depth/experiment/对照结果.md`）一致，两机位下几乎无增益。
- 分数蒸馏：太慢。
- IK 式扭转先验（2026-11-03）：exam 上无增益，代码已删除。

## 六、实施记录

### 测试方法

- 脚本：`work/ab_solver.py`。读取已保存的 `reading.npz`，只重新求解，不重新识别、不重新渲染；同一求解器的各变体拿到完全相同的观测。
- 真实视频：`Seedance25_Split_screen_two_loc_1793704727806`（121 帧，24fps）。指标：
  - 抖动 = 骨骼相对父骨骼的逐帧转动 / 转动变化（度）；`local` 为全身局部转角二阶差分 RMS。
  - `res` = 识别点与求解结果投影的偏差中位数（px）。
  - 打击感 = 三次挥手（正面画面，手的点）峰值速度（占体长 %）、从峰值 90% 降到 20% 的帧数、最大减速。
- exam：用原始 rig 评分（被冻结的骨骼仍按真值计入）。

结论：
- **A4（护目镜）有效，保留。** 冻结后护目镜抖动归零，其他指标不变，exam 不变。
  - 诊断修正：起初猜测是"杠杆短、观测不足"，但实测 Bone146 的转角测量精度在全身居中，真正特殊的是蒙皮：它的 1178 个顶点与其他骨骼的权重混合为 0%，而 m11101、lizard、dog_v2 的其他关节都是 17~100%。所以它是刚性挂件，不是关节。
  - 实现：`common.py` 新增 `rigid_accessories()`，prepare 时把"蒙皮与其他骨骼混合 < 2%（且至少 50 个顶点）"的活动骨骼设为跟随父骨骼，`--keep-bones` 可保留。只在 m11101 上命中 Bone146，lizard / dog / dog_v2 都没有命中。需要重新 prepare 才生效（rig.json 变化，之后需重训）。
- **A3（打击感）**：
  - 根因：temporal 的时间连贯性因子在三次急停帧把手的权重压到 0.05~0.4（中位 0.41），急停被当成识别错误。
  - `robust`（大加速度线性惩罚）单独使用：全面优于 temporal 基线——抖动更低、手部偏差更小、急停 3.0 帧、峰值速度回到 legacy 的 90%，exam 也是全表最好（1.40% / 8.4°）。**保留，候选默认值。**
  - `corroborate`（两机位一致的跳变不降权）单独使用：几乎无益，手部抖动反而变大。和 robust 合用时打击感最强（峰值超过 legacy），但全身抖动翻倍（0.61→1.42）。真实峰值不可知，需要急停考题判断是"恢复真实冲击"还是"放进噪声"。**暂留，待急停考题裁决。**
- 事故记录：第一版测试脚本在评分时以写模式打开了正式的 `exam/exam_report.json`，把它截成了 0 字节（12:26:58）。已用 `--regrade` 从未改动的 `out/exam/motion.npz` 原样恢复（1.45% / 8.7° / 7.4°，与之前一致），脚本已改为只向 `/tmp/v2r_ab_scratch` 写评分。

### 急停考题（A3 的验收）

- `gen_poses.py` 新增 `make_strike_motion`：静止 → 加速运动（2~4 帧，只缓入不缓出）→ 一帧内急停 → 静止，循环；所有关节同步，目标在关节限制内随机。
- `exam --style strike` 写入独立目录 `exam_strike/`、`out/exam_strike/`，不影响标准考题。
- 评分新增 `impact`：急停时运动最快的关键点保留了多少真值峰值速度、过冲多少、比真值晚几帧停下。
- m11101、lizard 各生成了一份（10 次急停，150 帧）。标准考题 `exam/exam_report.json` 生成前后 md5 一致。

### 决定

| 项 | 结论 | 处理 |
|---|---|---|
| **A4 刚性挂件跟随父骨骼** | 有效：护目镜抖动 0.65→0.00（legacy）、0.32→0.01（temporal），其他指标、exam 都不变 | **保留**。`common.py` 的 `rigid_accessories()`，prepare 时自动生效。在临时目录里对 m11101 完整跑过一次 prepare：只移除 Bone146（活动骨骼 23→22），关键点 48 个不变，其他骨骼限制不变。lizard / dog / dog_v2 不命中。**需要重新 prepare + 训练才会用到。** |
| **A5 手部刚体约束** | 无效：标记坏点本身是准的（exam 真值：被降权点误差 13.2px，保留点 5.3px），但降权后手的信息不够，legacy 和 temporal 下手部偏差都从 7.8~8.5px 升到 10.0~10.7px，急停考题也变差 | **删除**。`observations.py` 中的代码已移除。 |
| **A3 robust 加速度惩罚（0.003, 0.02）** | 有效：解决了 temporal 削弱打击感的问题。m11101 急停考题保留真值峰速 28%→54%（legacy 45%）、lizard 36%→59%（legacy 60%）；真实视频挥手峰值 7.7%→10.2%、急停 3.3→3.0 帧；抖动仍是 temporal 水平；标准考题两只都是全场最好或接近最好 | **保留，设为 temporal 求解器的默认**（`pipeline.py`）。legacy 不受影响。 |
| A3 更小尺度（0.0015, 0.01） | 考题打击感更好，但真实视频全身抖动 0.61→1.29、急停反而拉长到 5.3 帧 | 不采用，仅记录 |
| A3 corroborate（两机位一致不降权） | 单独用无益；与 robust 合用打击感最强，两只考题也最好，但 m11101 真实视频全身抖动翻倍（0.75→1.42）。考题里识别噪声比真实视频小，放大的部分在真实视频里很可能是噪声 | **保留为可选参数，默认关闭**，不接到网页。以后有更多真实视频时再评估 |
