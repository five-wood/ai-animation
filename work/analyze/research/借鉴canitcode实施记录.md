## 一、提示词：禁止特效（已写入文档）

`video2rig/README.md` 的 "Every new animation" 一节加了一条要求：提示词结尾要求画面干净（不扬尘、不加特效 / 发光 / 拖尾 / 模糊，手脚和手持物体始终可见），并说明原因：识别器只见过干净的渲染图，被特效盖住的手脚它照样给出位置，而且常常是错的。

## 二、多次读取取平均（TTA）

实现：`v2r/read.py`。每块画面按 `tta_views(n)` 读 n 次：第 1 次原图，其余在 4 px 的圆周上平移，并交替放大、缩小 4%。每份热图按逆变换采样回原网格（`_back_grid`），取平均后再解码。只在第二遍（按裁剪框读取）使用。`tta=1` 与原来逐像素一致（全片中位差 0）。

**m11101 结果**（exam / 急停考题有 2D 真值）：

| | tta=1 | tta=4 | tta=8 |
|---|---|---|---|
| 读取时间（150 帧，两画面） | 5.0 s | 10.8 s | 20.0 s |
| exam 识别误差（px，全部 / 可见 / 被挡 / 手） | 7.66 / 5.69 / 9.26 / 16.02 | 7.60 / 5.63 / 9.19 / 16.05 | 7.57 / 5.61 / 9.15 / 15.96 |
| exam 误差的逐帧变化（px） | 5.23 | 5.09 | 5.06 |
| 急停考题识别误差（px） | 7.92 | 7.71 | 7.70 |
| exam 求解（legacy / temporal，关节% / 肢体°） | 1.44/8.6，1.38/8.1 | 1.44/8.6，1.37/8.1 | 1.46/8.7，1.38/8.2 |
| 急停考题求解（legacy / temporal） | 2.64/13.2，2.84/12.9 | 2.70/13.0，2.70/12.5 | 2.61/12.6，2.74/12.8 |
| 真实视频：识别点跳动（px） | 0.50 | 0.43 | **0.38** |
| 真实视频 legacy：全身抖动 / 右手抖动 | 1.88 / 3.23·1.79 | 1.75 / 3.22·1.68 | **1.68 / 2.84·1.47** |
| 真实视频 temporal：全身抖动 / 右手抖动 | 0.63 / 0.84·0.19 | 0.62 / 0.85·0.24 | 0.69 / 0.81·0.19 |

**结论：收益小。** 识别误差只降 1~3%，求解结果在噪声范围内波动；真实视频的识别跳动降 24%，原解算器的抖动降约 11%，但实验版解算器已经平滑过，几乎看不出差别。参考仓库报告的手臂逐帧误差降低 34~47% 在我们这里没有复现，可能原因：我们的识别器已经读两遍（全图 + 裁剪框），且手部误差主要是系统性偏差（拳头上的手指点互相混淆），平均无法消除。

**处理：保留为可选参数 `animate --tta N`，默认 1（不变）。** 用原解算器处理抖动明显的视频时可以开 `--tta 8`，读取时间约增加到 4 倍。

## 三、帧率节奏

检查了三段真实视频（Seedance 生成，容器 24 fps，121 帧）：

- 时间戳均匀（每帧 1/24 s），没有 30→24 的丢帧换算。
- `Seedance25_Split_screen_two_loc_...`：有 44 帧与前一帧完全相同（静止段），运动段中"每 4 帧出现一次加倍步长"的迹象（第 3 相位平均步长是邻居的 1.96 倍），xiyi2 也有同样迹象（1.98 倍）。
- 但这几段的运动段都很短，静止段的重复帧本身就是"没有动"，加倍步长的样本只有 18~44 个；在这个数据量下无法可靠区分"内容帧率是 24 帧里有规律地少一帧"和"动作本身的节奏"。

**结论：暂不实现。** 现有视频不足以证明我们的 Seedance 输出存在固定丢帧模式；贸然重排时间会把真实的加减速当成丢帧修掉。以后有 5 段以上运动较多的视频，再用同样的脚本（`work/analyze/research` 里记录的方法：逐帧图像差、按 4/5/6 帧周期找相位）复查。

## 六、重训结果（2026-11-04 16:32~17:53，提交 72de05d）

命令即上面的建议命令（prepare --fist-points --offaxis-points、gen --contact-poses、train --steps 9000 --hidden-empty --smear 0.3）。
旧版备份：服务器 `/data/video2rig/backups/m11101-before-retrain-20261104-163223`。

### 结果

| 指标 | 旧版 | 新版 |
|---|---|---|
| 验证集可见点误差中位数 | 约 4.4 px（口径含被挡点） | **2.73 px** |

| 急停考题原始识别误差（可见点） | 5.33 px | **4.52 px** |
| 深度排序准确率（验证集） | 0.963 | 0.914 |
| **标准 exam** 关节 / 肢体 / 扭转 | 1.45% / 8.7° / 7.4°（通过） | **1.87% / 10.3° / 8.0°（未通过）** |

### 原因（已定位）

**识别器本身变好了，求解变差是因为身体中线的关键点被"教成了看不见"。**

- 可见性标注是"从相机到关键点的射线穿过几层表面"。骨盆根点 `Bip001`、`feature_Bone_*`、枪上的点在骨骼内部或被身体包住，在 3000 张训练图里**可见比例为 0%**；`Spine1`、`Neck`、尾巴等中线点只有 12~23%。
- `hidden-empty` 训练后，这些点几乎总是低可信度（exam 中中线 9 个点每帧在两个画面都 > 0.3 的个数：旧版 9 个，新版中位数 **2 个，最少 0 个**）。
- 两个求解器都靠中线点（权重 1.0，四肢 0.3）定身体的整体位置和朝向。中线证据几乎没了，整体朝向误差从 7.1° 翻倍到 15.6°，再传导到四肢（左大腿 20.8°→32.9°、尾巴 20.0°→29.8°）。
- 参考仓库的可见性判断看的是"关键点附近的屏幕像素是不是它自己这段肢体的皮肤"，而不是"射线穿过几层表面"；位于身体内部的关节，只要它那段身体朝向镜头就算可见。我们照搬了"被挡点空目标"的思路，却沿用了自己更严格的可见性定义，这是这次退步的根源。

### 真实视频上的两面

- 好：打击感明显恢复（挥手峰值 +40~46%，急停 4 帧 → 2~3 帧），护目镜不再抖。
- 差：手部和全身抖动变大（右手 1.08→1.48，全身 0.50→0.97），与身体整体朝向不稳一致。

### 下一步（未执行，待确认）

1. 把可见性改成"关键点所在肢体的皮肤在该像素附近可见"（用渲染时的骨骼 ID / 皮肤权重判断），只对真正被别的部位挡住的点用空目标。
2. 或者只对四肢末端（手、脚、指尖、外侧点）用空目标，中线和近端关节保持原来的训练方式。
3. 两者都需要重新 gen（可见性标注）+ 重训，约 80 分钟。在那之前，m11101 应回退到旧版识别器（旧版仍通过 exam）。
