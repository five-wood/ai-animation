## 0. 背景与目标

**项目**：`video2rig`。用 Seedance 生成的"左正面 | 右侧面"双画面视频，还原成怪物骨架动画并导出 FBX。
流程：每只怪物训练一个 DINOv2 关键点识别器 → 读出每帧每个画面的关键点 → 两个画面交叉定位 → 求解骨架姿势 → 导出。

**现在的问题**（主样本 m11101，兔子士兵，双足、拳头、持枪）：

| 指标（标准 exam，legacy 求解） | 当前值 |
|---|---|
| 关节误差 / 肢体方向 / 扭转 | 1.42% / 9.0° / 7.1°（及格线：肢体 ≤ 10°） |
| 身体整体朝向（root） | 9.0°（旧识别器是 7.1°） |
| 最差骨骼 | 左大腿 `Bip001 L Thigh` 32.2°、尾巴 `Bone004` 27.1°、左手 19.5°、右手 16.2° |
| 扭转最差 | 左前臂 15.2°、右前臂 14.7°、右上臂 14.6° |
| 急停考题 关节 / 肢体 / 保留峰速 / 停顿延迟 | 2.83% / 14.8° / 43% / 0.80 帧 |

原因判断：关键点只有 46 个，都在骨骼轴线上（看不出自转）；身体中线的点每帧只有约 4 个可信（被挡或在身体内部）；腿和尾巴短、常被挡住。

**目标**：在求解器里加入"模型表面"层面的约束，按以下顺序，每步都要 A/B 证明有效才保留：

1. 表面点 + 轮廓约束（不重训）
2. 用"完美"法线图 / 深度图测收益上限（不重训，只用考题）
3. 上限够大时，再决定真实视频的法线 / 深度从哪里来（识别器新增输出 / 现成单目模型）

**不在本计划内**：枪的处理（用户说暂时不管；它会污染轮廓，见 1.4 的处理）。

## 阶段 1：表面点 + 轮廓约束（不重训，约 1~1.5 天）

### 1.1 导出模型表面采样

新 Blender 脚本 `v2r/blender/export_surface.py`（用 `common.load_model` 加载，保证和 rig.json 同一坐标系、同一蒙皮修正）：

- 在网格表面按面积均匀采样约 2000~4000 个点（静止姿势，世界坐标），记录：位置、法线、所在三角形、**每点的骨骼权重**（取前 4 个，归一化）。
- 标记"枪"等非身体部件的点：权重主要落在没有父骨骼的独立根骨骼上（m11101 的 `22101_weapon`、`25101_*`）的点，存 `is_prop`。
- 输出到项目目录 `surface.npz`（新文件，不改其他文件）。`cli.py` 加子命令 `export-surface <project>`。

### 1.2 torch 线性蒙皮

在 `geom.py` 加 `Skeleton.skin_points(world, surf)`：

- 每根骨骼的变换 = 当前世界矩阵 × 静止世界矩阵的逆。静止世界矩阵就是 `G = 单位阵`、全部欧拉角为 0 时 `fk` 的结果。
- 点位置 = 各骨骼变换按权重加权后作用于静止位置；法线用加权旋转再归一化。
- **验证**（写成测试）：用 Blender 对考题某几帧的 GT 姿势求出变形后的网格顶点，和 torch 结果比较，误差应 < 0.5% 体长。

### 1.3 轮廓提取

新模块 `v2r/silhouette.py`：

- 考题：可以直接用 RGBA 帧的 alpha 当真值，用来**评测**提取算法。
- 视频（考题视频和真实视频）：灰色摄影棚背景。逐像素在时间上取较亮的分位数估计空背景；前景 = 与背景颜色差大的像素；去掉阴影（阴影只变暗、色度接近背景）；形态学去噪。输出每画面每帧的二值轮廓，降到 1/4 分辨率存 `masks.npz`。
- **验收**：在考题视频上和 alpha 真值比，IoU ≥ 0.95（两只怪物都要测）。

### 1.4 求解器新增两项（`fit_temporal` 和 `fit` 都加，默认关闭）

- **模型落在轮廓内**：所有表面点（包括被挡住的，模型的任何点都应投影在整体轮廓内）投影后，查轮廓外部的距离变换，罚出界距离。
- **轮廓被覆盖**：在轮廓内随机取像素，罚它到最近投影表面点的距离。用稳健损失并设上限。
- 枪：`is_prop` 的点不参与；轮廓里枪的像素会让"覆盖"项把手拉偏，所以覆盖项必须用有上限的稳健损失，必要时把轮廓里远离身体投影的细长区域排除。在记录里写明影响。
- 参数：`silhouette_strength`（默认 0）、`coverage_strength`（默认 0）。权重从小往大扫，比如 0.1 / 0.3 / 1。
- `ab_solver.py` 要能读 `masks.npz`（先单独跑一次提取并存到临时目录）。

### 1.5 A/B 与保留条件

在 m11101 和 lizard 的 exam、急停考题，以及 m11101 真实视频上比较。**保留条件**：

- 两只怪物的 exam 和急停考题都不变差（关节 +0.05% 以内，肢体 +0.2° 以内）；
- 且身体整体朝向、左大腿、尾巴三项中至少一项改善 ≥ 2°；
- 真实视频手部抖动、全身抖动变差不超过 10%，挥拳峰值不降超过 10%。

不满足就删掉求解器里的新代码（表面导出和蒙皮工具保留，后面阶段要用）。

## 阶段 2：用"完美"法线 / 深度测收益上限（不重训，约 1 天）

目的：在花钱做法线估计之前，先知道"就算法线完全正确，能好多少"。

### 2.1 渲染真值法线 / 深度

新 Blender 脚本 `v2r/blender/render_passes.py`：读 `exam/frames/motion_gt.json` 的每帧姿势（`G`、`quat`，用 `common.apply_pose`），用和考题相同的相机，渲染法线通道和深度通道，存成 npz（每画面，降到 1/4 分辨率，float16）。输出到**临时目录**，不要写进 `exam/`。

- **必须先验证坐标系**：Blender 法线通道是世界坐标还是相机坐标、深度通道是到相机平面的距离还是到相机点的距离，各版本 / 渲染器不同。用一个已知顶点对照 `common.project()` 和法线方向确认，再转换成统一的相机坐标法线和相机平面深度。
- 关掉运动模糊。

### 2.2 求解器新增两项（默认关闭）

- **可见性**：每轮（或每 50 轮）在 `no_grad` 下用点云投影做简易 z 缓冲（1/4 分辨率，每格保留最近的表面点），得到每个表面点在每个画面是否可见。不需要可微渲染库。
- **法线项**：可见表面点的预测法线（蒙皮后转到相机坐标）与该像素真值法线的夹角，罚 `1 − cos`，稳健处理。
- **深度项**：两种都测。
  - 绝对深度：考题有真值，测理论上限。
  - **每帧尺度和偏移未知的相对深度**：每帧先用最小二乘拟合一个尺度和偏移再算误差。这才是真实单目深度能提供的信息，以它的结果为准。
- 参数 `normal_strength`、`depth_strength_dense`，默认 0。

### 2.3 A/B 与决策

变体：阶段 1 最佳 / + 真值法线 / + 真值深度（相对） / + 两者。两只怪物，exam 和急停。

**进入阶段 3 的条件**（相对阶段 1 最佳）：真值法线（或深度）让 m11101 的身体整体朝向改善 ≥ 2°，或肢体方向改善 ≥ 1°，或扭转改善 ≥ 1.5°，且 lizard 不变差。都达不到就停在这里，在记录里写明，不要继续。

## 阶段 3：真实视频的法线 / 深度从哪来（阶段 2 通过才做）

两个来源，**都先在同样的两个检验上量误差，再决定**：

- 考题视频：有真值法线和深度（来自 2.1）；
- 真实视频第 0 帧：就是我们自己的渲染图（静止姿势），用 2.1 的脚本对静止姿势渲染真值，先用 `pipeline` 里的首帧校准把画面对齐。

### 3A. 识别器多输出一张法线图

- 生成训练图时（`gen_poses.py` random 模式）多渲染法线通道，训练时给识别器加一个逐像素法线输出头，和关键点一起训练（`train.py`）。
- 成本：渲染多一遍、存储约 1 GB、训练时间略增。**需要重训，先征得用户同意。**
- 风险：只见过渲染图，换到 Seedance 画面上会打折扣。用真实视频第 0 帧量化这个差距。

### 3B. 现成的单目法线 / 深度模型

- 候选（**每个都必须先核实许可证是否允许商业 / 游戏使用，未核实不得接入**）：Marigold（深度 / 法线）、StableNormal、DSINE、Metric3D v2、Depth Anything V2（不同大小的模型许可证可能不同）、Sapiens（仅人体，可能是非商业许可）等。
- 优点：在真实图像上训练过，不怕 Seedance 的画风变化。缺点：不认识这只怪物；深度只有相对值。
- 只在服务器的独立环境里试，不要污染 `/data/video2rig/.venv`。如需新环境，另建 venv。

### 3C. 接入

选定来源后，把阶段 2 的法线 / 深度项接到真实视频的处理流程里（`pipeline.animate` 新可选参数，默认关），在真实视频和两场考试上再做一次完整 A/B，满足阶段 1 的保留条件才保留。
