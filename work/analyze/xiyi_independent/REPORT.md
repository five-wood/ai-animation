# xiyi 拒绝原因：独立定量核查

分析日期：2026-11-02。仅新增分析脚本和输出，没有改核心、阈值、模型或训练。帧号均为 **0-based**，24fps。视频121帧、1280×720、640处分割。

## 结论

1. **46/121拒绝完全由射线误差触发，骨长不触发。** screen size归一化分母310.790863px，3%即9.323726px；46个bad全在31..89。骨长误差全片中位5.75065%、最大14.2850%，均低于原35%条件。
2. **没有证据支持一个固定侧视延迟能解释或修复主要问题。** -12..12帧扫描，固定frame0位移基线、固定前视帧集、固定置信度样本集、极线矫正后的纵向位移RMSE，全运动段的整体/中轴/肢体最优都在0帧。
3. **四肢大于中轴，但中轴也不是完全一致；尾部尤其明显。** 运动段中轴帧中位射线误差2.966%，四肢3.910%，尾部4.390%；不应把问题全部归到左右交换。
4. **真实帧可明确证明至少一处高置信读错：frame82前视tail4.tip(19)。** 其实际可见尾梢约(150,397)，读取(268.392,430.651)，偏约123px，落在身体/前肢区域；conf=0.858，不能靠现有confidence识别。其他遮挡关节仅能说可疑，不能当作可见真值。

## 数据与指标

- 使用服务器项目 /data/video2rig/projects/lizard；源码只读 /data/video2rig/code。
- reading.npz中uv是fix_swaps后的读点，uv_raw是交换前读点（不是未经校准图像点）；conf未做clean_tracks降权。res是检查阶段的两视角重投影残差，形状121×28×2。**保存的X在pipeline中被后续降权重三角覆盖，而res没有重算，所以不能直接用保存X重现检查的骨长；本报告骨长来自check.json，延迟重三角从uv/conf重新算。**
- 中轴12点：0..6以及15..19；肢体16点：7..14以及20..27。中轴包含尾巴，另列头躯7点与尾巴5点。
- 每点ray error取两视角res最大值，仅保留两视图conf>0.3；每帧跨组点取中位，再在帧间取中位。这与原check的聚合顺序一致。P90是点级分布而非帧级。

## 固定帧位移同步扫描

**延迟约定**：front(t)配side(t+d)，正d表示用更晚的侧视帧；24fps下1帧=41.67ms。扫描d=-12..12（±500ms），运动集固定t=31..89，不随d裁剪。另用全片共同重叠t=12..108验证。严格位移扫描对每点在全部25个d都要求conf>0.3，固定样本1598个点帧（中轴664、肢体934），避免置信样本变化产生假最优。

相机不是完全水平正交，直接比较原图y位移会混入透视/俯视效应。因此用studio相机中心基线构建共同极线矫正坐标，焦距选1500，将每视图每点相对自己frame0的rectified-y位移相减：

`error(t,k,d)=[rectY_front(t,k)-rectY_front(0,k)]-[rectY_side(t+d,k)-rectY_side(0,k)]`。

## 真实帧核查

查看源帧及读点覆盖（不是solve后FK投影），抽样0、24、31、45、60、69、75、82、85、89、96、120。

### 明确可见读错

- **frame82，前视，19 tail4.tip**：原视频尾端在图左约(150,397)，读点却回到(268.392,430.651)，离可见尾端约123px；18 tail4已经位于(157.384,395.171)，于是18→19边异常折返到前肢。conf19=0.858。该帧19的射线误差只有8.675px，小于9.324px阈值：**低射线残差并不证明语义标签正确。**
- **frame85，前视，19读到x=-4.4**，视频尾端也出画；不能说这个外推坐标一定错，应标注“尾端不可见、无真值”，不拿它作确定错误。

### 可疑但无法仅凭画面精确判错

- frame45/60/69前视尾端被身体遮挡或与后肢混叠，尾点18/19落在身体/腿区域。遮挡时没有可观察的尾梢，不能据此给精确2D真值或断言某个像素读错。
- frame31、45、60、75中远侧腕/踝与近侧肢体严重重叠；多个13/14/26/27读点残差高，但单张灰度/无纹理画面不能可靠区分近远侧骨点身份。3次swap修正远不足以说明所有剩余不一致都是真实动作不同。
- frame82/85/89明显转身/尾巴抬起，原“front/side”镜头标签只表示原始相机方向，不表示角色始终正对/正侧；不能直接用两图相同y作为准确同步真值。

## 限制

1. 分析针对既有reader输出与studio标定，而不是人工2D ground truth；无法给出“视频不同步”和“reader错误”的独立百分比分解。
2. frame0含点级偏差；已做固定frame0扣除、前三帧均值备选和相机极线校正，但无法恢复被遮挡的真实点。
3. 射线一致性只是两条视线能否相交；语义点共同读错也可能低残差。骨长的中位聚合也会隐藏少数严重异常，所以骨长小不等于所有关节准确。
4. 只搜索固定±12帧延迟，不排除局部时变相位差、生成形变、镜头微变或更大的偏移；现有扫描不支持为了过检而固定剪8帧。

## 建议（不改代码/阈值/训练）

- 先在独立标注文件手工审计12张抽样帧，优先19、18、13/14、26/27；将可见性和左右身份分开记录，别把遮挡关节强行标真值。
- 对可见且有明确语义的头/胸/肩和脚端，手工修正少量点后仅重跑同一原检查，比较bad数，才能区分输入真实几何不一致和reader失败。
- 保留原视频和严格拒绝结果；不要因为骨长好或全片median1.58%就绕过运动段46/59失败。
- 若必须重生成素材，要求两视图来自同一个严格同步动作、固定角色比例/相机/地面、避免大幅转身和尾肢重叠；本次分析无须也未做重训。
