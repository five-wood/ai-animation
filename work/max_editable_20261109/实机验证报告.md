# 3ds Max 2026.2 实机验证报告

日期：2026-11-09。对象：m11101 原角色，Biped + Bone。原始场景：[11101_01(10.22).max](../../11101_01(10.22).max)。

## 结论

已在现有 Max 2026.2 会话中执行脚本，不是仅离线生成代码。已完成原生场景检查、独立副本回写、实际 Max 曲线减键对比、合成脚 IK 支撑及 COM 二次编辑测试。

**这是验证原型，不是源动作无损交付。** 减键新增误差已控制，但源动画包含 Biped 原生肘部不能表达的非铰链旋转；需要后续把拟合端改成 Biped 可实现的姿态约束，或采用可保留相应自由度的普通 Bone 控制结构。

## 2. 源拟合到原生 Biped 的偏差：不能与减键误差混淆

独立原生参考：[native_retarget_reference.max](native_retarget_reference.max)。

该参考已经使用Max原生Biped及普通Bone，而不是导入FBX替换rig。它是诊断性重定向结果，**源保真验收未通过**。

### 已修复/处理

- 单位、rest basis、Max行矩阵与源列矩阵转换。
- 普通Bone节点旋转与matrix.rotationpart的差异，通过同姿态隔离实验验证。
- 将源Pelvis增量吸收到COM以适配Biped内部COM→Spine继承，使上身原约9.84mm统一偏移降低到约0.03mm量级。
- 足部原生世界朝向显式设置，避免仅大腿旋转却脚方向被Biped内建机制改变。

### 剩余主要问题

源普通FK的Pelvis→Spine、Neck→Clavicle继承与Biped内部继承不同；源前臂允许独立三轴旋转，而Biped肘部是受限铰链。

重定向参考相对源采样的最大误差示例：

| 部位 | 最大位置差 | 最大世界旋转差 |
|---|---:|---:|
| Spine / Head | 约0.03mm | 约0.03° |
| 左手 | 约0.93mm | 约0.03° |
| 右手 | 约2.83mm | 约0.03° |
| 左前臂头点（肘部） | 约45.77mm | 约16.78° |
| 左上臂 | 约14.68mm | 约41.72° |
| 右上臂 | 约14.24mm | 约31.98° |
| 左右脚关节 | 约0.003mm以内 | 约0.05°以内 |

上述足部数字是已采样时刻的转换残差，不代表源动作脚已站稳，也不是地面接触精度。前臂差异不能靠增加keys或改TCB切线消除。

详情：[原生重定向误差](native_retarget_report.json)。

## 3. 满帧原生参考 → 稀疏关键帧

可编辑副本：[editable_sparse.max](editable_sparse.max)。

对同一原生参考，比较自研保守减键与Max原生动捕减键。后者关闭footstep extraction，设置位置容差0.15cm、旋转容差1.5°、Minimum Key Spacing=1，执行后恢复mocap全局参数。

采样：60Hz + 源24Hz精确时刻，共361个时刻；检查Max实际求值，包括30fps整数帧和半帧。

| 版本 | 关键时间数 | controller-key统计 | 对原生满帧参考最大位置差 | 最大角度差 | 当前预算 |
|---|---:|---:|---:|---:|---|
| 原生满帧参考 | 121 | 5445 | 0 | 0 | 参考 |
| 自研保守稀疏 | 70 | 3150 | **1.30mm** | **0.73°** | 通过 |
| Max原生mocap减键（一次参数试验） | 217 | 3319 | **17.53mm** | **2.07°** | 未通过 |

注意：

- 70/121约减少42.1%的关键时间，**还不是美术理想的少量主要姿势**，只是安全的还原优先基线。
- controller-key统计去除了普通Euler/Position聚合父轨重复，但Biped共享肢体存储还有特殊语义；不把它当独立美术pose数量。
- Max原生结果只代表本次参数和输入，不代表产品普遍效果；其时间数量增加说明转换包含重新采样/时间处理，而不是简单删原keys。
- “自研减键通过”只相对于原生重定向参考，不会消除上一节的源→Biped偏差。

报告：[候选对比](candidate_comparison.json)、[自研减键过程](reduction_report.json)。Max原生对照：[native_mocap_reduced.max](native_mocap_reduced.max)，当前不作为推荐交付。

## 4. 脚部 IK 定帧与实际二次编辑

测试场景：[ik_support_test.max](ik_support_test.max)。

**这是一段明确的合成验证动作，不是视频重建，也没有自动认定源动画接触区间。**

- 原rig，0/30/60帧三个时间点。
- 双脚先建立独立世界IK参考（首键IK Blend=1、Object、Join=false），后续Planted keys（Join=true）。
- COM在第30帧下降1cm，再恢复。
- 随后只改第30帧COM，将下沉改为1.5cm，**不改脚键**。
- 以半帧采样检查支撑。

结果：

- 初始下沉和COM单独二次编辑后，两脚锚点最大位置差均约 **0.0013mm**（接近数值精度，不是现实动画测量精度承诺）。
- 原1cm下沉的膝弯约43°；没有通过逐帧腿部FK补键实现脚锁。
- 说明该原rig在此base layer、双脚支撑、可达姿态下支持美术描述的编辑方式。
- 不证明任意上层、任意骨盆旋转、换步、脚尖滚动、不可达姿态都正确。

详情：[IK支撑报告](ik_support_report.json)。

## 5. 源数据的下肢限制

源样例只有大腿参与独立拟合；小腿、脚和脚趾局部旋转为identity，膝盖几何弯曲约0.88°、接近伸直。

按同角色尺度，源左脚距首帧最大水平漂移约22.7mm、右脚约7.0mm。若锁首帧双脚且原样保留身体轨迹，理想两骨几何已有不可达帧，最大需要约2.6mm的身体高度补偿（未计目标限位、膝弯余量、碰撞）。

因此不能把合成IK实验通过等同为“源动作自动锁脚完成”。真正源动作的接触修正需要：人工确认支撑段、足底offset与朝向、允许的身体补偿范围，然后另存独立结果并报告主动修正量。

## 6. 下一步建议

1. 美术分别检查稀疏副本和IK测试副本：前者看动作/编辑点，后者改COM深度看支撑。
2. 拟合端引入Biped合法的膝/肘自由度与正确position/rotation parent模型，避免源阶段生成不可回写姿态；小腿/脚观测不能继续被不加检查地折叠。
3. 稀疏化从“全身共享70个时间”升级成“主要poses + 分部位breakdowns”，以实际编辑耗时而非key总数为目标。
4. 将人工确认接触区间接入脚部原生IK，再做源→修正→稀疏三段误差报告。
