# ladingwu 可编辑动画：生成与实机验证报告（2026-11-11）

> **美术审核结论（11-11）**：关键帧的姿态不好，键数偏多。本版保留，作为对照基线；后续改走 [关键帧优先方案](../../video2rig/docs/关键帧优先方案_20261111.md)。

- **源数据**：服务器上的 `projects/m11101_tex/out/ladingwu_temporal`。
  - 视频 [ladingwu.mp4](../../ladingwu.mp4)，193 帧，24fps，8 秒。
  - 读取器 m11101_tex，temporal 求解器，`bad_frames=0`。
  - 本地副本：[m11101_tex_ladingwu](../maxkeys/m11101_tex_ladingwu/)。
- **骨架核对**：m11101_tex 与写入用的 Max 场景是同一副骨架。176 根骨骼名称、父子关系一致，rest 差 < 3e-5。
- **目标场景**：[base_scene.max](../max_editable_20261109/base_scene.max)。用 `3dsmaxbatch` 无界面写入，另存为 [spline_edit.max](spline_edit.max)，播放范围 0–240 帧。
- **文件保护**：原始角色文件 SHA256 不变；base 不变；11-09 和 11-11（m11101）的输出不变。

## 流程与新增能力

本 clip 有换脚和转身，比 m11101 那段原地站立复杂得多。在 11-11 整体方案的基础上补了以下能力：

| 能力 | 实现 |
|---|---|
| 自动判断着地 | [detect_contacts.py](../../video2rig/tools/max2026/detect_contacts.py)：用读取器三角化出的脚点（不用求解后的腿，因为小腿被折叠成了直棍）。正面视角置信度足够才采用；按速度阈值判定；快速转身段强制两脚都离地；短暂抬脚合并；保证至少一只脚支撑。输出 [contacts_plan.json](../maxkeys/m11101_tex_ladingwu/contacts_plan.json)，标记为 `reviewed=false` |
| 多段着地与离地 | 每段着地单独定锚点，在“腿够得着”的前提下尽量靠近观测到的脚位；着地段边缘腿够不着的帧改为离地；不足 3 帧的着地段取消；离地段每约 6 帧打一个 free 键，脚抬离地面 1–5cm |
| 按帧下沉身体 | 只在着地段按需下沉（保证膝盖至少弯 15°，另加 0.6cm 余量吸收 COM 插值的过冲），并做平滑。不再像上一版那样整段统一下沉 |
| 锁骨规则修正 | 从 Max 实测中确认：Biped 锁骨的局部 Y 轴始终垂直于 Spine1 的局部 X 轴，三份样本误差都在 0.0008 以内。合法化模型改用这条规则，锁骨写入偏差从 8.6° 降到 0°（上一份报告列出的遗留问题已解决） |
| 着地保持键 | Max 实测发现：身体转动时，着地脚会绕接触点转动，24 帧内脚踝漂移 1.28cm、转动 8.6°。在着地段内每个 COM 键处（间隔不超过 8 帧）加一个 planted join 键后，降到 0.5cm 以内、4° 以内。改该段第一个键时，整段仍会一起移动（已实测） |

**迭代过程**：`draft0` 到 `draft5` 是逐步修正前的中间版本，都保留在对应的子目录里。

## 结果

### 关键帧

每两个姿势键之间 1–3 个过渡键，全部在整数帧上。

| 部位 | 姿势键 + 过渡键 | 超出容差的区间 |
|---|---|---|
| COM | 28 + 28 | 无 |
| 躯干/头 | 35 + 38 | 190–197 帧（1.95cm，转圈期间） |
| 左臂 / 右臂 | 39 + 45 / 38 + 48 | 无 |
| 左耳 / 右耳 | 12 + 18 / 11 + 14 | 无 |
| 尾巴 | 10 + 9 | 无 |
| 左脚 IK | 49 个键：3 段着地，含 28 个保持键，另有 15 个 free 键 | — |
| 右脚 IK | 45 个键：5 段着地，含 8 个保持键，另有 27 个 free 键 | — |

合计 467 个键，满帧版本是每根骨骼 241 个键。

**排键容差**：这段 clip 的手腕高频抖动 p90 为 3–4cm，所以容差用了宽一档（姿势键 2.0cm、过渡键 1.5cm）。若要窄档（1.0 / 0.8cm），需要 408 个身体键；宽档是 373 个。

| COM/躯干 | 2.59 / 0.95 | 2.59 / 0.95 |

- **合法化本身带来的变化**（离线计算，不含脚）：max 3.83 / p95 2.30cm。
- **手臂**：拟合残差约 3.7cm，手腕偏移 2.7 / 1.0cm，肘部偏移 3.3 / 2.2cm。
- **左肘**：17 帧处在铰链极限（伸直）上，对应源数据中 17 帧肘部弯向了 Biped 转不过去的方向。

### 脚与膝盖

| | 左 | 右 |
|---|---|---|
| 着地段内脚踝漂移最大 | 0.44cm | 0.53cm |
| 着地段内脚转动最大 | 3.8° | 3.5° |
| 着地时膝盖弯曲 | 32–85° | 24–123° |
| 离地时脚趾最低点 | 0.27cm | −0.10cm（第 125 帧穿地约 1mm） |

**身体下沉**：最大 5.07cm，平均 1.84cm。第 0–50、120–150、210–240 帧较多，原因是源数据的脚悬在离地 5–12cm 处，但小腿是直的。

### 编辑测试

- **只改一个 COM 键**：第 45 帧（双脚都着地）下移 1.5cm。双脚漂移基本不变（左 0.44 → 0.44cm，右 0.53 → 0.53cm），左膝最大弯曲 85° → 91°。结果另存为 [com_edit_test.max](com_edit_test.max)。
- **移动着地段第一个键**：右脚第 134 帧的键平移 3cm 后，134–158 帧整段跟着平移约 2.3cm（求解器把位置夹在腿长允许范围内）。段外的帧只受插值影响（0.4–0.5cm）。

## 遗留问题

1. **着地区间未经人工确认。** 第 50–130 帧左脚被判定为一直着地，依据是正面视角的观测，侧面深度只有部分可信，而且读取器在这一段的置信度有间断。
2. **转圈段双脚都离地。** 按道理应该有一只脚作支点，需要美术处理，或者改进着地判断。
3. **身体下沉最多 5cm。** 这是“源数据小腿是直的 + 脚悬空”的直接后果。要从根本上解决，需要拟合端提供可靠的小腿和膝盖观测（对应 11-10 交接文档 8.1 节）。
4. **键数偏多。** 手臂部分接近满帧的 35%，原因是动作密集、源数据抖动大。可以考虑先对源做时间平滑再排键（原型已有 `--smooth-sigma` 参数，但会改变挥拳的速度峰值，这次没有启用）。
5. **工具还没封装好。** 目前需要手动设置环境变量 `V2R_RUN` 再运行 batch，换角色需要重新提供 profile。
