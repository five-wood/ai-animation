# 动画层做法：用途、在 Biped 里能做到什么、怎么用在我们的方案里

- **日期**：2026-11-11
- **地位**：调研和设计稿，**还没有在 Max 里实测**。与 [关键帧优先方案](关键帧优先方案_20261111.md) 配合使用，不替代它。
- **标记**：【官】Autodesk 官方文档写明；【推】根据官方说法推断，需要实测；【社】社区经验；【测】我们在 ladingwu 上算出来的数据。

**一句话**：动画层把一段动画拆成“底层 + 叠加层”，播放时两者相加。我们可以把**少量关键姿势放在底层**给美术改，把**关键姿势插值不出来的细节放在上层**。上层可以随时关掉或删掉，美术改底层时细节会跟着走。

---

## 一、动画层是什么

普通动画每个控制器只有一条曲线。打开动画层后，同一个控制器有多条曲线叠在一起，最终姿势 = 底层 + 各叠加层：

| 概念 | 含义 |
|---|---|
| 叠加（additive） | 上层存的是偏移量，加到下层的结果上。上层某帧没有键时，按插值得到偏移量 |
| 覆盖（override） | 上层直接替换下层，常配合权重做淡入淡出 |
| 权重 | 上层作用的强度，0–100%，可以打动画 |
| 静音 / 激活 | 临时关掉一层，数据保留 |
| 塌陷（collapse） | 把上层合并进下层，变回一条曲线 |

它最大的好处是**改动可逆，而且互不干扰**：底层不动，改动都放在上层，不满意就关掉或删掉上层。

## 二、业界怎么用

### 2.1 主流：满帧动捕放底层，美术在上层改

MotionBuilder 和 Maya 清理动捕时的常规流程【官】：

1. 动捕数据放在 BaseAnimation 层，每帧都有键，基本不动。
2. 美术新建 Additive 层，只在需要改的地方打少量键。用“零键”框住影响范围：区间两端各打一个偏移为 0 的键，中间打一个偏移键，这样修改只在这段区间内平滑起效。
3. 每层可以单独静音、调权重、独奏（solo）。
4. 定稿后合并（MotionBuilder 的 Merge，Maya 的 Merge Layers），或者 Plot 回骨骼导出。Maya 还能把某层单独提取出来（Extract）。

3ds Max Biped 的层也是这个思路【官】：只打一个键，就是对整段的整体偏移；在区间前后用 **Snap Set Key** 打“回到原动作”的键，就是限定区间的修改（官方叫 envelope）。

### 2.2 理论来源：位移映射

学术界很早就把这类做法形式化了：

- **Motion Warping**（Witkin & Popović 1995）：用少量类似关键帧的约束，对原曲线做平滑变形，原动作的细节保留下来。
- **Motion Signal Processing**（Bruderlin & Williams 1995）：把动作当信号，分成多个频带分别调节，并提出了 displacement mapping（位移映射）。
- **Hierarchical Displacement Mapping**（Lee & Shin 1999）：每帧用 IK 满足约束，再用多层 B 样条拟合出位移，让修改平滑地传到周围帧。

**结论**：“原动作 = 平滑骨架 + 位移（细节）”是成熟的分解方式。动画层就是这种分解在软件里的落地。

### 2.3 两种分法正好反过来

| | 业界主流（2.1） | 我们可以考虑的分法 |
|---|---|---|
| 底层 | 满帧动捕 | 少量关键姿势（结构键 + 前 k 个过渡键） |
| 上层 | 美术的少量修改 | 底层插值不出来的细节（位移） |
| 改姿势 | 在上层打偏移键 | 直接改底层的关键姿势，细节跟着走 |
| 改节奏 | **困难**：层只能偏移姿势，不能挪时间 | 直接挪底层的键 |
| 噪声 | 底层带着读取抖动 | 细节层只放去抖后的部分 |

美术这次的反馈是“姿态不好、键太多”，而且改节奏是动画师最常做的事，所以我们倾向第二种分法。第一种分法几乎不用开发，可以作为对照提供（见第四节方案 A）。

## 三、3ds Max / Biped 里能做到什么

子代理按官方文档整理，来源见文末。

### 3.1 Biped 自己的层（Motion 面板 → Layers 卷展栏）

| 项目 | 情况 |
|---|---|
| 叠加方式 | 【官】层上的键是偏移量（官方原话 offset / increment），只打一个键就是对整段的整体偏移 |
| 偏移在哪个空间 | 【推】旋转是各骨骼的局部偏移，COM 位置是世界空间平移。官方只说“移动 COM 可以整体平移动画”，没写具体空间 |
| 插值 | 【推】跟 Biped 的 TCB/四元数一样；【官】Euler 部件建层时会先转成四元数，塌陷时再转回去 |
| 静音 | 【官】每层有 Active 开关（第 0 层不能关）；脚本：`biped.setLayerActive <ctrl> <index> <bool>` |
| 权重 | 【官】**Biped 层没有权重**，只能开关、删除、塌陷 |
| 显示 | 【官】**播放时只显示当前层及其下方的激活层**。在第 0 层操作时看不到上层效果，想看合成结果，当前层必须切到最顶层。卷展栏里还有 Visible Before / Visible After 选项，用来参照相邻层，具体显示方式待实测 |
| 塌陷 | 【官】Collapse 把当前层并入下方最近的激活层；脚本：`biped.collapseAtLayer <ctrl> <index>` |
| 脚本接口 | 【官】`createLayer / deleteLayer / numLayers / getCurrentLayer / setCurrentLayer / getLayerActive / setLayerActive / getLayerName / setLayerName / collapseAtLayer / setSnapKey`；**没有**复制层、设权重、Load/Save Layer 的脚本接口。索引从 0 还是从 1 开始需要实测 |

### 3.2 层和脚 IK（最需要小心的地方）

- 【官】Layers 卷展栏有 **Retargeting** 组，作用是在上层改动作时保住底层的手脚 IK 位置：可以分别勾选左右手、左右脚（Retarget Left/Right Arm/Leg），点 **Update** 会在**已有键的帧**上重新算手脚位置。官方示例：上层把 COM 压低以后，只有勾了 retarget 的肢体保持不动，勾上双腿并点 Update 之后，脚才被拉回原位。
- 【社】planted 键只在底层真正生效，上层移动 COM 时，整个身体连同脚都会跟着走。还有早期版本的报告：底层带 planted/sliding 键时塌陷出错。
- 【推】如果上层只是稀疏键，Update 只修正有键的帧，键之间的脚仍可能滑动。

**由此得到的设计原则**：细节层**不碰 COM 和腿**，只放脊柱、头、手臂（以及耳朵、尾巴）。这样底层的脚 IK 完全不受影响。下面的实测数据说明这样做代价很小。

### 3.3 普通骨骼（耳朵、尾巴）

【官】用 Max 通用的 Animation Layers 工具栏（Biped 部件不走这个，官方让 Biped 用自己的 Layers 卷展栏）。功能更全：每层有可打动画的权重、静音、锁定、塌陷；旋转可以选“Pose to Pose”混合方式。

### 3.4 想要权重怎么办

Biped 层没有权重。有两条路：

1. 【官】Biped 的 SubAnim（每个部件位置、旋转、缩放上的加权 List 控制器），权重可以打动画。但它不支持 COM，官方建议配合 freeform 使用。我们的场景本来就是 freeform 加 IK 键，可行性需要实测。
2. 我们离线把细节按比例生成，比如 50% 版本。最简单，但美术不能在 Max 里实时调。

### 3.5 保存和导出

- 【官】FBX：必须**在最顶层并勾选 Bake Animation**，才能导出所有层的合成结果；不勾 Bake 只导出顶层。最稳妥的做法是导出前先塌陷。
- 【官】`.bip` 的 Save Layer 只保存当前层；XRef 引用时会先把多层塌陷成一层。
- 【推】`.max` 文件会保存所有层，需要实测确认。

## 四、ladingwu 上的数据【测】

用 [breakdown_ladder.py](../tools/max2026/breakdown_ladder.py) 的同一套离线近似计算，统计非转圈段（cm，四个部位取最大）：

| 底层键数 | 底层漏掉的真实动作（细节层要承担的部分） | 读取抖动 | 转圈段漏掉的部分（最大） |
|---|---|---|---|
| 34（只有结构键） | p95 9.2，最大 14.9 | p95 2.1 | 24.2 |
| 39（+5 个过渡键） | p95 4.0，最大 6.0 | p95 2.1 | 24.6 |
| 50（+16 个，建议值） | p95 1.8，最大 2.6 | p95 2.1 | 24.6 |

“底层漏掉的真实动作”指去抖参照与底层插值之差，“读取抖动”指原始合法化动作与去抖参照之差。

按部位看（50 个底层键，原始动作减底层，非转圈段）：COM p95 0.7、最大 1.1；躯干 p95 1.7、最大 2.7；左臂 p95 2.8、最大 3.8；右臂 p95 2.4、最大 3.5。换成局部旋转：手 p95 2.5–3.5°，上臂 p95 2.7°，Spine1 p95 1.7°。

从中能读出四点：

1. **底层越稀疏，细节层越有价值。** 只有结构键时，细节层要补回 9–15cm 的真实动作；底层已有 50 个键时，只剩 2cm 左右，这时细节层主要装的是读取抖动，意义不大。
2. **细节层必须从去抖后的参照生成，不能直接用原始动作。** 否则一半内容是噪声，美术打开细节层反而会看到抖动。
3. **COM 的细节很小**（最大 1.1cm），不放进细节层几乎没有损失，同时避开了脚 IK 的问题（3.2）。
4. **转圈段是细节层最大的用处。** 那里补关键帧降不下来（约 24cm），手臂的细节交给细节层逐帧承担，比硬塞过渡键合适。

## 五、三种落地方案

| | A：满帧底层 + 美术编辑层 | **B：关键姿势底层 + 细节层（推荐试）** | C：只做参照影子 |
|---|---|---|---|
| 底层 | 合法化后的逐帧动作 | 结构键 + 前 k 个过渡键（键数滑杆） | 关键姿势 |
| 上层 | 空层，美术自己打偏移键 | 去抖后的细节：脊柱、头、手臂（加耳朵、尾巴），不含 COM 和腿 | 无；另放一个半透明“影子”角色播放原动作，不进入曲线 |
| 改姿势 | 上层打偏移键加 Snap 键框区间 | 直接改底层关键姿势，细节跟着走 | 改关键姿势，对照影子 |
| 改节奏 | 很难 | 挪底层的键 | 挪键 |
| 还原度 | 最高，但带抖动 | 打开细节层接近去抖参照；关掉就是纯关键姿势 | 只有关键姿势 |
| 开发量 | 最小（已有满帧导入） | 中：写细节层、Max 实测 | 小 |
| 主要风险 | 美术之前已经反馈过满帧难改 | Biped 层的空间语义、脚 IK、塌陷，都要实测 | 影子只能看，不能直接用 |

**推荐 B**，A 可以顺带做出来作对照。B 和键数滑杆是同一件事的两头：滑杆决定多少细节放进底层的键里，其余的交给细节层。美术也可以把滑杆拉到 0，只拿 blocking，再打开细节层看效果。

### 5.1 B 的细节层怎么生成

1. 底层定下来后（结构键 + 前 k 个过渡键，取精拟合后的姿势），在 Max 采样出底层的逐帧结果。必须在 Max 里实际采样，不能用离线近似，因为 Max 的 TCB 和我们的近似有差别。
2. 目标 = 去抖后的合法化逐帧动作。转圈段同样采用不平滑的版本（与阶梯的参照一致）。
3. 细节 = 目标局部旋转 ×（底层局部旋转）⁻¹，逐帧逐骨骼计算，只算脊柱、颈、头、锁骨、上臂、前臂、手。肘部仍要遵守 Biped 单轴铰链：直接写“目标局部旋转”，让 Biped 自己计算偏移，比我们手算偏移更安全，需要实测确认哪种可行。
4. 写入方式：在第 1 层（命名为 `V2R_细节`）逐帧打键。可以再按 0.5cm 或 1° 的容差抽稀，减少键数；这一层美术一般不改，键多一点问题不大。
5. 默认状态：层是激活的，当前层设为第 0 层，美术打开文件后直接改底层。播放时（当前层为 0）看到的是纯关键姿势；要看合成结果，切到第 1 层。这样的显示方式是否顺手，要问美术。

### 5.2 美术怎么用

- **改姿势**：在第 0 层改关键姿势，切到第 1 层看加上细节后的效果。
- **不要细节**：关掉第 1 层的 Active，或者直接删掉这一层。
- **定稿**：把第 1 层塌陷到第 0 层，或者导出 FBX 时在顶层勾选 Bake。
- **细节在某段不对**：在第 1 层用 Snap Set Key 把那几帧的偏移清零。

## 六、风险与待实测项

| # | 要确认的事 | 为什么重要 | 判定标准 |
|---|---|---|---|
| 1 | 层键在什么空间叠加：旋转是否为局部偏移，COM 是否为世界空间 | 决定细节能不能跟着底层的修改走 | 底层手臂姿势改动 30° 后，合成结果中的细节仍然在手臂局部坐标系里 |
| 2 | 第 1 层不碰 COM 和腿时，底层 planted 脚是否完全不受影响 | 方案 B 的前提 | 脚漂移与没有细节层时相同（< 0.5cm） |
| 3 | 肘部铰链：在层上写偏移，或者写目标旋转，Biped 怎么处理 | 合成后可能超出铰链限制 | 合成后与目标的偏差 < 1°，不出现反关节 |
| 4 | `setLayerActive` 关闭后是否完全回到底层；索引从 0 还是 1 开始 | 开关是美术最常用的操作 | 关闭后逐帧回采与只有底层时的差 < 1e-3cm |
| 5 | 塌陷：结果是否等于合成，底层的 planted/sliding 键是否保留 | 有旧版本出错的报告 | 塌陷前后逐帧差 < 0.01cm，IK 键类型不变 |
| 6 | FBX 在顶层勾选 Bake 后，导出是否等于合成 | 交付到引擎 | 与 Max 回采的逐帧差 < 0.01cm |
| 7 | 第 1 层逐帧打键的耗时和文件大小 | 实用性 | batch 能在几分钟内完成 |
| 8 | 当前层为 0 时，美术能否借助 Visible After 一类选项看到上层效果 | 美术体验 | 问美术 |
| 9 | Biped 层和通用 Animation Layers（耳朵、尾巴）同时使用时的表现 | 统一开关 | 两套层分别开关，都正常 |

**实测方案（可以先于精拟合做，不依赖它）**：

1. 以 [spline_edit.max](../../work/max_editable_20261111_ladingwu/spline_edit.max) 的写入流程为基础，把底层换成 ladingwu 的 50 个全身键（结构键 + 16 个建议过渡键，换算到 30fps），用 batch 写入并回采。
2. 新建第 1 层，逐帧写入脊柱、头、手臂的细节，回采合成结果。
3. 逐项跑上表第 1–7 条，结果写进验证报告。

## 七、结论

1. 动画层是业界改动捕的标准工具，理论上对应位移映射。它适合我们的场景：底层放关键姿势，上层放细节。
2. Biped 层只有开关，没有权重；上层不会自动保住 planted 脚。所以细节层不放 COM 和腿，只放上半身。按 ladingwu 的数据，这样做的代价是 COM 最多 1.1cm。
3. 细节层要从去抖后的动作生成；底层越稀疏、转圈这类难打键的段落越多，细节层越有价值。
4. 下一步：先按第六节做 Max 实测，确认 1–6 项。全部通过后，把细节层作为可选输出，和关键姿势版一起交给美术。
