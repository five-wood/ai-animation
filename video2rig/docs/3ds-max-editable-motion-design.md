# 3ds Max 可编辑动画交付方案：支撑感知的稀疏关键帧 + 原生 Biped / Bone

> **2026-11-11：本文是早期设计稿，当前主方案见 [可编辑动画整体方案](可编辑动画整体方案_20261111.md)。** 两者冲突时以新方案为准。

- 日期：2026-11-07
- 初始状态（2026-11-07）：设计稿；当时未在 3ds Max 中运行验证。
- 更新（2026-11-09）：已在原始角色的独立副本上进行 Max 2026.2 实机检查、原生回写、减键与合成 IK 支撑测试；工具为 [Max 2026 验证原型](../tools/max2026/README.md)。**原生 Biped 的肘部自由度/内部继承与源普通 FK 存在差异，不能宣称源动作无损导入。** 后文为初始方案，实际结果以工作输出报告为准。
- 范围：保留现有拟合/导出默认行为；不覆盖原始角色场景，不把原型或单项测试通过称为已达到完整美术交付标准。

## 1. 目标不是最小文件，而是可继续创作的动作初稿

现有满帧动画适合作为参考、回放和引擎烘焙产物，但不适合美术逐键修改。新交付应另开一条编辑链路：

```text
现有满帧拟合结果（保留不变，作为参考）
    ↓
骨骼角色映射 / 目标绑定标定
    ↓
接触与动作阶段标注（机器建议、人工确认）
    ↓
脚部支撑 → 重心/骨盆 → 腿型 → 躯干 → 手臂/头部 → 附加骨
    ↓
目标控制器感知的稀疏关键帧拟合
    ↓
编辑数据包 + Max 导入工具
    ↓
写入美术原有 Biped + Bone，在 Max 真实控制器中评估并回采验收
```

关键决策：

1. **保留原始骨架、蒙皮、骨长和约束关系**，不把原生 Biped 换成 FBX 普通骨架。
2. 支撑脚使用合适的 IK / 支撑机制，上身、摆动肢体和附加骨按需要用 FK；不要求全身一律 FK。
3. 关键帧数量服从编辑意图和误差预算，不承诺任意动作都能固定压成几帧或某一压缩比。
4. 可编辑版与原满帧参考版分开；最终交引擎时再按需烘焙，不在编辑导入末尾重新全身满帧打键。
5. 视觉重建提供的是姿态/运动估计，不是测得的真实接触力或精确物理重心。由下往上整理是动画编辑策略，不冒充动力学恢复。

因此，不建议只改 FBX simplify factor。它既不表达接触语义，也不保证原生 Biped 的编辑体验。

### 2.2 本地 m11101 样例揭示的风险

根据 [rig.json](../../work/maxkeys/m11101/rig.json) 和本地 motion 数组元数据：

- 共 176 根骨骼，22 根 active；样例 121 帧、24 fps。
- 世界矩阵包含约 `0.01` 的缩放及轴向变换，不能假设 Blender 数值原样填进 Max 即可。
- Biped 与普通 Bone 混合：既有 Biped 风格节点名，也有手部附加骨、Twist、肩带、面部等节点。
- 左右 Thigh 为 active，Calf / Foot / Toe0 在这份 prepared rig 中没有独立参与局部旋转拟合。

`active=false` 不等于静止：它仍会随父骨骼运动；也不等于真实角色不需要该自由度。脚/小腿姿态可能只是继承或先验结果，不能自动当作可信完整 foot transform。应分别记录接触区间、位置证据、朝向证据，并允许未知与人工校正。

首版前置检查应把“当前下肢解算自由度不足”列为独立风险：核实是否需要调整 prepared rig 的观测点/active 配置，或由目标 Biped 的 IK 根据经确认的足目标重建腿型。这两种操作都会改变动作，应生成独立副本并重新评估；单纯减键不能修复原本缺失的膝盖/脚部动作。

另有 [keyreduce_probe.py](../../work/keyreduce_probe.py) 做过通道级减键可行性探针，其 Euler/根路径误差和自定义 Hermite 插值不能替代世界末端误差与 Max 实机评估；本方案不据此承诺减键比例。

## 3. 把“脚定帧”拆成明确的编辑语义

### 3.1 已确认：美术在脚部打 IK 定帧

用户已更正实际工作方式：**脚部打 IK 定帧，建立支撑，再往上处理身体动作**。这不是要求整条腿纯 FK；方案应直接保留脚部 IK 支撑，不将它烘焙成满帧腿部 FK。具体 IK 键类型、参考空间和接触切换方式，待原始 Max 场景就绪后核实，不能仅凭“IK 定帧”认定其所有参数。

作为实现边界，普通层级 FK 满足：`foot_world = parent_world × foot_local`。局部 FK 定帧不能替代上述 IK 支撑。

不同编辑语义仍需区分：

| 美术意图 | 所需机制 |
|---|---|
| 保持脚相对小腿的局部姿态 | FK 关键帧即可 |
| 脚踩在地上，修改身体时仍保持支撑 | Biped 世界空间 IK / planted，或普通 Bone 的真实 IK / 世界约束 |
| 坚持全链 FK，但修改身体后还要原地踩住 | 工具根据 anchor 重求解腿部，再把结果转换成 FK；不是实时自动锁脚 |
| 脚沿地面滑动 | 移动的 IK 接触目标，不能误当 planted，也不等于 FK |
| 脚跟抬起、脚尖支撑、滚脚 | 显式接触点/转轴和姿态变化，不应锁死整只脚的六自由度 |

据此确定主路线：**脚部 IK 定帧 + 重心/骨盆等身体控制 + 分部位稀疏关键帧**；身体和上肢按现有 rig 与美术习惯进行 FK/控制器编辑。纯 FK 重算只作为可选扩展，不是当前需求，也不作为首版交付前提。

### 3.2 支撑约束要表达自由度

每段接触至少区分：

- `flat`：近似全脚掌支撑；姿态可靠时才约束完整朝向。
- `toe` / `heel`：只固定对应点，允许合适的转动。
- `sliding`：接触目标随地面移动。
- `free`：无支撑约束。
- `unknown`：证据不足，不强锁。

位置、朝向、转轴分别开关和带置信说明。脚踝关节位置不一定在地面；需从脚踝到脚底/脚尖的局部 offset 定义接触点。ground 需由场景或人工校正确定，模型包围盒最低点不自动等于真实地面。

## 4. Biped 与普通 Bone 分开适配

### 4.1 原生 Biped 路线（主路线）

官方接口说明 Biped 使用专用变换/打键方法；`biped.setTransform` 的位置和旋转是世界空间，位置可能受 IK 限制，并要求设置位置时从 root 沿层级向下处理。[1]

实现约束：

- COM/root 与 Pelvis 单独映射；COM 的水平、竖直、转向轨道分开管理，不把 COM 当普通 PRS 骨。
- 不把 Blender 的局部 `quat` 直接传给 Biped；先经过 rest basis、世界轴、单位和绑定标定转换。
- 支撑腿保留脚部 IK 目标；膝盖朝向/腿型通过合适的姿态和 Biped 控制能力保持，避免伸直翻膝。
- 使用 `biped.setPlantedKey` / `setSlidingKey` / `setFreeKey` 表达对应接触类型；这三个接口在官方文档中存在。[2]
- Separate FK Tracks 是可编辑分轨配置，不是锁脚。导入前确定一次分轨策略并记录；不在处理中反复开关。[4]
- 不要求每根 Biped 逐帧独立打键；统计实际轨道 keys，而不只统计请求写入了多少节点姿态。

官方接触语义：[3]

| 类型 | IK Blend | 空间 | Join to Previous IK Key |
|---|---:|---|---|
| Planted | 1 | Object | 开 |
| Sliding | 1 | Object | 关 |
| Free | 0 | Body | 关 |

注意：Object 且未指定 IK object 才是完全 world space；指定了对象则相对该对象。Body 随 COM。Join 复用前一个 IK key 的参考位置，**不等于自动在当前脚位置新建一个独立锚点**。新接触段先建立目标与参考关系，再接后续 planted；首帧/退出接触的实际打键顺序必须在 Max 验证，不能仅靠接口名称猜测。

首版场景约束：

1. 原角色先在 Figure Mode 完成比例设置，退出后导动画；不改骨长，不写逐帧 scale。
2. 优先 freeform、base layer 0；检测并阻止未确认的 footsteps / mixer / 既有复杂层冲突。
3. 不承诺“上层改一次骨盆，脚永远自动锁”。官方跨层维护约束有腿部 Retarget + Update 流程；Load Layer 到高层还涉及移除 limb IK 和 separate tracks 的特定限制。[5]
4. 先让 base layer 接触可验证，再支持跨层编辑；能力由实测确认。

### 4.2 普通 Bone 路线

在 Max 中按实际控制器和绑定关系分类，不能仅凭名字中含 `Bip` 或 `_Bone` 决定：

| 分类 | 导入策略 |
|---|---|
| 原生 Biped 控制节点 | 专用 Biped adapter |
| 有独立动画意图的普通 Bone | 若控制器可写，导入稀疏 FK 旋转/必要位置 |
| 跟随/约束/表达式驱动的变形 Bone | 保留驱动；不重复把整段绝对动画写入 |
| Twist / 补偿骨 | 保留既有驱动，或经确认后单独拟合；不默认强打键 |
| 不能可靠观测的手指、面部、装饰骨 | 默认保留原动作/原姿态或略过，并报告，不生成虚假精细动画 |
| 有自定义动画控制器的 Bone | 映射到真正控制器；未支持则停止/跳过并明确报错 |

不能为了“导入成功”就替换 Position/Rotation Controller、删除约束或重绑 Skin。普通 Bone 若也需要站立锁脚，应使用其现有 IK rig，或者独立提供显式求解工具；Biped planted API 不对普通 Bone 自动生效。

## 5. 稀疏关键帧生成：先动作结构，后误差补键

### 5.1 两个可选产物

- **Blocking / 创作优先**：主要姿势、接触事件、节奏点；可选 stepped 预览，方便改剪影、节奏和幅度。接受适度偏离 AI 源动作。
- **Spline / 还原优先**：相同动作结构基础上增加必要 breakdown，保留节奏、支撑、末端轨迹；采用与目标控制器匹配的插值。

两者不冒充同一个优化目标。“最少关键帧”宜表述为：在允许的动作偏差和支撑约束内，尽量少、位置有意义、容易修改。

### 5.2 固定必须保留的事件

片段首尾；接触进入/退出；左右支撑切换；重心最低/最高或明显转折；起跳/落地；蓄力/冲击/恢复；手与物体的接触；人工指定 poses / breakdowns。

关键时刻不必全身同时打键。采用“全身主要姿势 + 部位成组的补充关键帧”：

- 根/骨盆、左右腿、躯干、左右臂、头、尾/附属骨分别管理。
- 同一肢体的关键帧适当对齐，减少各轴散乱 keys。
- 不为一个手腕的小修正给全身所有骨骼补一帧。
- 支撑期间脚目标可保持常值，但重心和腿型仍可有少量必要 keys；不能由此承诺整段动作只需首尾两帧。

### 5.3 拟合与补键循环

```text
保留事件 + 部位初始 keys
    ↓
按目标插值重建完整时间段
    ↓
用 FK / 目标控制器计算世界姿态
    ↓
检测末端、接触、姿态、时序误差
    ↓
在最严重且有可信依据的部位补 key / 调整切线
    ↓
再次评估；满足阈值或达到预算后输出明确结果
```

- 接触段是优先约束，不是最后用平滑掩盖滑脚。
- 拟合根和骨盆时考虑双脚可达性与膝弯，随后允许受限的联合微调，避免严格逐层冻结导致无解。
- 骨盆/身体参考点不等同物理质心，`G` 也不直接等于 Max COM。
- 旋转内部用 SO(3)/四元数距离评估；需要可编辑 Euler 时在目标 basis 中选连续分支、处理 wrap/奇异性。
- 不拟合四元数四分量的普通独立 Bezier 后就认为会等价于 Max 旋转控制器。
- 普通 Bone 的可控 Bezier/Hermite 与 Biped 的原生 TCB/IK 插值分开；离线近似只能用于候选筛选，Max 回采才是最终依据。
- 清理不可信抖动与拟合误差分开记录。异常帧不能逼迫算法无限补键，也不能被不透明地删除。
- 达到最大键数仍超差时，报告问题区间/原因；不悄悄放宽误差或偷偷退回满帧。

### 5.4 误差与编辑成本

建议按项目设置预算，首轮仅作调参起点，**不是当前已达到的指标**：

- 支撑点滑动/高度误差：真实尺寸确认后以 mm 为主，例如 2–5 mm；也保留体型百分比便于怪物尺寸归一化。
- 手脚等末端的世界位置：例如体型尺寸的 0.5%–1%，重要接触应更严格。
- 局部/世界旋转误差：例如 1–2°，还需看长肢体末端放大误差。
- 关键事件时序偏差：例如不超过 1 个源帧；冲击点可要求固定不动。
- 地面穿透、不可达/伸直腿、膝翻转、脚跟/脚尖接触分别检查。
- 同时记录 major pose 数、每条实际轨道 key 数、总 keys、接触类型和人工修正数，不能只报“保留 N 个帧”。

检查源采样时刻与必要子帧，避免关键帧之间的 spline overshoot。没有真实 GT 时，误差主要衡量相对源参考的偏离和接触约束满足度，不能称为真实动作精度。

## 6. 接触生成以“建议 + 复核”为起点

第一版优先人工选择左右脚的支撑区间，复用现有项目显式确认而不是自动强锁的原则。

后续自动建议可综合：脚底/脚尖相对地面高度、世界速度、持续时间、双视角可见性/一致性、身体运动和源画面。用滞回和最小时长避免抖动切换；不能仅凭“速度低”或“脚在画面里没动”就确认为支撑。

输出状态：candidate / approved / rejected，以及来源（人工、启发式、外部标签）。必须支持修改区间、锚点、朝向自由度及整段禁用。

- 地面、支撑对象或朝向未知时不自动贴地，更不能把 ankle 高度压成 0。
- 两脚支撑但目标骨盆超出腿长时报告不可达，优先给出调整骨盆/anchor 的选择，不拉伸骨骼。
- source 为 forced diagnostic preview 时，编辑版也保留未验证标签；不能因稀疏化而“洗成合格”。

## 7. 数据包与 Max 工具交付

以下是**拟议交付物名称和职责**，不是已经实现或验证的文件：

```text
editable_motion.zip
├─ manifest.json             # 版本、源输出标识/hash、fps、时长、单位、轴、验证状态
├─ motion.edit.json          # sparse keys、poses、部位组、曲线/插值语义
├─ contacts.json             # 接触区间、锚点、自由度、证据、审核状态
├─ rig_profile.json          # 源 rest、语义映射、目标标定/适配标识
├─ reference_samples.jsonl   # 可选：压缩的满帧参考，供误差回采比较，不写入编辑轨道
├─ quality_report.json       # 离线误差、keys 数、未知/失败项，不冒充 Max 验收结果
└─ reference.fbx             # 可选：原满帧参考；不用于覆盖原生 rig

Max 工具：
  V2R_RigInspect.ms          # 只读扫描当前选择角色、单位、控制器、层、约束、rest 标定
  V2R_ImportEditable.ms      # UI、映射、预检、导入、回滚、接触预览
  V2R_ValidateEditable.ms    # 真实场景采样、误差报告、回导信息
  可选配套 Python 模块      # 通过目标 Max 的 pymxs / JSON 支持读取数据和运行适配器
```

JSON 解析方案应在确定 Max 版本后选择。可用 MAXScript UI + Max 自带 Python 标准库解析 JSON，但需要验证版本兼容；不把任意文本作为 MAXScript `execute` 来解析，不从网络动态拉执行代码。

### 7.1 协议必须明确的字段

| 类别 | 必需信息 |
|---|---|
| 版本与状态 | schema 版本、tool 版本、源 hash、是否 forced/needs_review、目标 profile ID |
| 时间 | fps 的有理数、源样本数、源时间原点、导入起始时间、单位是秒/帧/ticks、末端时刻定义 |
| 空间 | source unit 与来源/未知状态、目标 system units、轴向/手性、统一缩放、变换应用次序 |
| 旋转/矩阵 | quaternion 分量顺序、矩阵存储顺序、列/行向量约定、local/world/rest_delta 语义 |
| 骨骼 | source ID、name、parent、rest transform、语义角色、目标节点映射、driver/deform/skip 策略 |
| 关键帧 | 部位/轨道 ID、时间、值、插值和切线参数、mandatory/事件原因、置信/来源 |
| 接触 | 足/手、起止时间及开闭区间定义、空间、anchor、局部接触点、位置/朝向约束开关、审核状态 |
| 验收 | 离线评估与 Max 回采结果分开、keys 预算、阈值、未支持/超差区间 |

统一内部约定可采用：右手坐标、列向量 4×4 变换、JSON 按行存矩阵、`wxyz` 四元数；Max adapter 负责转换到 Max matrix3 / quat 约定。**同为 Z-up 不代表局部轴、矩阵约定和单位相同**，不能只换 quaternion 分量顺序就完成适配。

时间以秒作为跨工具基准，用 fps 有理数映射到 Max ticks；默认不悄悄改变场景帧率，不通过取整帧来改变动作时长。端点最后一个样本在 `(sample_count-1)/fps`，与视频容器总时长分开记录。

### 7.2 两阶段角色标定，比硬编码节点名更可靠

1. Max 读取美术原始场景，选择角色根和参考姿势，只读导出 profile。
2. 人工确认 COM/Pelvis、左右肢体、普通 Bone 的 driver/deform 分类，以及脚底 offsets。
3. 以该目标比例和 rest basis 生成目标感知的候选动作；初期仅支持同角色/同拓扑回写。
4. Max 导入 sparse keys，评估真实 Biped/普通控制器结果；有偏差则回传 profile + 采样报告用于再拟合。

暂时拿不到 Max profile 时，可以先实现通用数据导出与离线减键，但必须标记 target-unvalidated；不宣称“直接导入任意 Biped”。不同角色比例重定向是后续独立能力，不混入首版验收。

### 7.3 导入 UI 与安全边界

流程：选择数据包 → 选择 rig root/profile → 映射预览 → 预检 → 查看/修正接触 → 选择 Blocking/Spline 与导入区间 → 导入 → 验证/报告。

- 默认不覆盖已有动画，不自动清空全场景 keys；已有动画/footsteps/layers 时要求明确选择新副本或指定区间策略。
- 显示将修改的节点、轨道、接触状态及不支持项目；失败前尽量在预检阶段停止。
- 尽可能用 Max undo 事务，但不将 undo 当唯一安全措施；建议导入到另存的场景/独立角色副本，失败回滚并保留日志。
- 不修改蒙皮、骨长、命名、父子层级；不擅自切换有损配置、删除约束或覆盖控制器。
- 保护未映射/未观测的骨骼及源片段之外的 keys；对层/约束写入支持不充分时明确拒绝，不静默降级。
- 可分步导入：先“支撑脚+重心+腿”，验收后再“躯干+头”，最后“上肢+附加骨”。
- 概念上的由下往上规划，不等于 API 写入顺序；Biped 世界空间位置仍按官方 root→子级顺序处理，最终重评估接触。
- 支持预览接触点、轨迹、膝盖方向、主要 poses；辅助标记不必成为永久场景依赖。

## 8. 实施阶段与当前能验证的范围

### P0：无 Max 先完成的工作

- 固化版本化编辑包协议、时间/单位/空间约定。
- 映射与接触标注分离；人工区间优先。
- 对通用 skeleton 做姿势/部位分组、事件保留、四元数/位置拟合、FK 末端误差和地面约束测试。
- 保留原始结果；另建 editable 输出，不改变现有导出默认行为。
- 建合成测试：双脚下蹲、单脚移重、步行换脚、起跳/落地、脚尖支撑、滑步、转身和不可达 anchor。
- 明确离线误差边界，不把自定义插值视为已验证的 Max 结果。

### P1：本地 Max 建好后的最小闭环

- 先做只读 RigInspect，核实实际 Max 版本、原生 Biped 标识、单位、层、约束、骨底 offsets。
- 仅支持同一角色、原生 Biped、freeform/base layer 0 + 无冲突的普通 Bone。
- 首个验收动作选“双脚支撑下蹲/起身”：脚支撑明确，便于直接检验编辑体验。
- 先导支撑/COM/腿，再导身体与上肢；必要时从 Max 回采后补少量 key。
- 明确区分“导入完成”和“编辑体验/误差验收通过”。

### P2：扩展

自动接触候选；toe/heel/roll 细化；跨层 Retarget；已动画场景合并；不同体型重定向；控制器级自动修复；批量交付。每项单独验收，不作为首版隐含保证。

## 9. 本地 Max 验收清单

| 场景 | 要验证的结果 |
|---|---|
| 参考姿势往返 | rest basis、尺度和轴向一致；蒙皮不变形、左右不互换 |
| 相同角色的纯根平移/转向 | COM 三轨与 Pelvis 无重复变换、无方向翻转 |
| 双脚支撑下蹲 | 脚底接触稳定；骨盆高度/俯仰可改；无腿拉伸/反膝 |
| 单脚支撑移重 | 仅支撑脚锁定，摆动脚能自由改；换脚无 snap |
| 前后两次落脚到不同位置 | 新 anchor 不错误继承旧 planted reference |
| 起跳/落地 | 空中没有误锁；接触首尾及过渡符合时间点 |
| 滑步、脚尖支撑、滚脚 | 不误判为全脚掌刚性 planted；应保留自由度 |
| 修改 COM 与修改 Pelvis | 分别检查支撑结果，不把两者当同一编辑 |
| 普通 Bone/变形/Twist | 保留原驱动，无双重运动；真正独立骨可编辑 |
| 24/25/30/非整数 fps、非零起始帧 | 时长、事件时间、ticks 映射正确，无累计漂移 |
| 改关键帧时间与曲线 | 动作仍可编辑；子帧无明显过冲、穿地 |
| 骨盆超出腿可达范围 | 明确报错/警告而非静默伸骨/跳脚 |
| 已有层/footsteps/约束 | 预检阻止不支持组合，不覆盖已有工作 |
| 跨 Biped layer 修改 | 经 Retarget/Update 流程单独验收，不混入 base layer 保证 |
| 撤销、取消、失败重试 | 不留下半次导入、不丢原 keys、不改 rig 结构 |
| 重新打开场景 | 动画与接触不依赖临时脚本状态，可继续编辑 |

还需要一次美术操作验收：能否只改少量 poses/脚接触/骨盆 keys 完成目标修改；不能仅以压缩率、播放不报错代替。

## 10. 建议交付结论

采用 **“原始满帧参考 + 接触感知稀疏编辑包 + 原生 Max 适配工具”**，先实现同角色回写。默认 **支撑脚 IK、身体/上肢 FK、附加 Bone 按驱动关系处理**。按腿部支撑到上身的顺序组织工作，但内部保留全身一致性检查和受限联合修正。

当前先完成协议与离线算法；Max 就绪后先用双脚下蹲动作跑通最小闭环，再扩展。不能把“删帧后的 FBX”或“未运行过的 MAXScript”当作已达到美术编辑需求的成品。
