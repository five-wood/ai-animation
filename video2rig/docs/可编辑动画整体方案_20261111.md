# 视频动作转成美术可编辑动画：整体方案

> **2026-11-11 傍晚更新**：美术审核 ladingwu 版本后反馈“关键帧姿态不好、键数偏多”，打键方式已改为 **[关键帧优先方案](关键帧优先方案_20261111.md)**：先定关键姿势、逐个精拟合、中间交给 Max 插值。本文第二节第 ③ 步和第四节第 3 条“各部位各管各的”已被替代；其余内容仍然有效。

- **确定日期**：2026-11-11（已与用户确认）
- **适用范围**：video2rig 生成的拟合动作 → 3ds Max 中美术原有的 Biped + Bone 角色
- **本文地位**：这是当前的主方案。[3ds Max 可编辑动画方案（11-07 设计稿）](3ds-max-editable-motion-design.md) 和 [11-10 交接文档](交接_可编辑动画与3dsMax_Biped_IK_20261110.md) 中与本文冲突的部分，以本文为准。差异见第八节。

**一句话**：AI 从视频里读出动作，我们把它翻译成美术角色骨骼做得到的动作，再按动画师的习惯，在关键位置打少量关键帧，交到美术自己的 3ds Max 场景里继续改。

---

## 一、为什么现在的 AI 动画不好改

AI 拟合出来的是**满帧动画**：每一帧、每根骨头都有一个键。

这就像把一段舞蹈每 1/30 秒拍一张照片交给美术。照片很全，但美术想“让手抬高一点”，就得把几十张照片逐张改一遍，改完还容易抖。

动画师自己做动画不是这样。他们先摆几个**关键姿势**（起点、最低点、最高点、停顿），中间补少量**过渡帧**，其余交给软件自动补间。要改的时候，只动那几个关键姿势就行。

所以我们要交付的，应该是动画师自己会做出来的那种关键帧，而不是一叠照片。

---

## 二、整体分四步

```text
① AI 看视频           ② 翻译成 Biped 能做的动作      ③ 像动画师一样打键         ④ 写进美术的 Max
   得到动作参考    →     （关节规则、脚踩稳）     →    （脚 → 重心 → 上身 → 手臂）  →  （不动原绑定）
```

### ① AI 看视频（已有）

用正面和侧面两个视角的视频，算出每个关节每一帧的位置。这份结果**只当参考**，原样保存，不直接交给美术。

### ② 翻译成 Biped 能做的动作

AI 用的骨架比较“自由”，美术的 Biped 骨骼有自己的规矩，比如：

- 肘只能往一个方向弯，像门的合页；
- 锁骨不能绕自身扭转；
- 骨盆跟着重心（COM）走。

AI 的动作里有些 Biped 做不出来。以前是硬塞进去，结果左上臂歪了 40 多度。现在先按 Biped 的规则“意译”：**在规则允许的范围内，找最接近视频的姿势。** 手腕位置几乎不变，只有肘部的位置做了小幅调整。

同时决定**脚踩在哪**。AI 读出的脚会有 1–2cm 的漂移，多半是误差，所以我们把脚钉在地上固定的点。为了钉住后膝盖不被拉直，身体整体略降一点（这段样例是 0.67cm）。

### ③ 像动画师一样打键

按美术习惯，**从下往上**来：

| 顺序 | 部位 | 怎么打键 |
|---|---|---|
| 1 | 脚 | **IK 定帧**：脚钉在地上，每段着地的开头和结尾各一个键 |
| 2 | 腿 | **不打键**，Biped 根据脚和重心自动算出腿的弯曲 |
| 3 | 重心（COM） | 少量姿势键，管下蹲、起身、移重 |
| 4 | 躯干/头、左右臂、耳朵、尾巴 | **各自独立**打姿势键 |

打键规则有三条：

- 每个部位只在**自己需要的时候**打键。手臂快速抬起就多打几个，躯干几乎不动就少打。
- 每两个姿势之间放 **1–3 个过渡帧**，保证直接播放就顺。这是 spline 版，用户已选定。
- 所有键都在**整数帧**上，美术在时间轴上容易选中。

### ④ 写进美术的 Max

在美术原角色的副本上写入，**不碰**蒙皮、骨长和原有的约束，原文件里已有的键（武器辅助点、面部等）都保留。写完后在 Max 里实际播放、逐帧回采，核对是否符合预期。

## 三、美术拿到的是什么（以 m11101 这段 5 秒的样例为例）

| | 以前（满帧） | 现在 |
|---|---|---|
| 键的数量 | 每根骨头 121 个 | 整个角色共 120 个，按部位分开 |
| 脚 | 每帧一个键，会滑 | 两个 IK 键，全程钉住 |
| 想加深下蹲 | 逐帧改腿和身体 | **只改 1 个重心键**，脚不动，膝盖自动多弯 |
| 想改手臂 | 几十帧一起改 | 改 1 个姿势键，再看看两边 1–3 个过渡帧 |
| 和视频像不像 | 原样 | 大部分偏差 1cm 左右，最大约 2cm |

关于最后一行：AI 从视频读动作，本身就有大约 1cm 的误差。所以把毫米级的抖动删掉不算损失，删掉的大多是噪声。

---

## 四、几个关键取舍

1. **不追求毫米级还原。** 精度够用就行，目标是好改。误差容差按源数据本身的精度来定（厘米级）。
2. **还原度不靠堆关键帧。** 设想在 Max 里放一个半透明的“影子”，显示 AI 原动作，美术改的时候可以对照，但它不进入动画曲线（尚未实现）。
3. **各部位各管各的。** 改手不会给全身加键，改重心不会让脚跑掉。
4. **哪里改过就明说。** 脚是我们判断后钉住的，左肘是因为 Biped 做不到才伸直的。这些都写进报告，不当作“无损还原”。

## 五、现在做到哪了（2026-11-11）

**已经做到的**（m11101 这段原地站立的片段，在 Max 2026.2 里实测）：

- 写进原角色副本，原文件没被改动（SHA256 不变）；
- 脚 IK 钉住，改重心时脚不动（双脚漂移小于 0.001mm）；
- 分部位关键帧，全部整数帧，每段 1–3 个过渡帧；
- 手臂按 Biped 规则重新拟合，以前上臂歪 40 多度的问题消除了；
- 原文件里已有的 675 条非 Biped 曲线全部保持不变。

**还没做到的：**

- **美术还没实际试改**，这是最关键的检验；
- 左肘全程伸直，需要看视频确认原动作是不是这样；
- 锁骨写入时有 1–2 度的小偏差，待修；
- 只做了“原地站立”。走路换脚、单脚站、跳跃需要判断“哪只脚什么时候着地”，还没做；
- 现在是我们在本机跑脚本生成，还不是美术能自己点按钮用的工具。

## 六、接下来怎么走

| 阶段 | 做什么 | 怎样算完成 |
|---|---|---|
| **近期** | 美术试改 3 件事：加深下蹲、改手臂、改节奏；确认左肘；修锁骨偏差 | 美术觉得比满帧明显好改，记录用时和改了几个键 |
| **中期** | 支持走路、换脚、跳跃：机器先猜脚什么时候着地，人确认后再生成 | 换脚不跳变、不滑步，腾空时脚不被误锁 |
| **后期** | 做成 Max 里的工具：选数据包 → 预览 → 确认着地 → 一键导入 → 自动检查；换角色、换电脑也能用 | 美术不用找我们就能自己导入 |
| **最后** | 接进网页生成流程，生成动画时顺带输出“可编辑版” | 满帧版和可编辑版同时提供 |

## 七、需要配合的事

1. **找美术试改一次**，告诉我们哪里顺手、哪里别扭。后面的方向主要看这个反馈。
2. **看一眼原视频里左臂是不是伸直的**。
3. **确认以后主要做哪类动作**（原地表演、走跑、攻击、跳跃）。这决定下一步先攻哪种“脚着地”的情况。
4. 原场景里 `Dumm_input` 在第 164–173 帧有一段飞出动画（疑似子弹或特效定位点）。如果要和 AI 动作拼接，需要确认时间怎么对齐。

## 八、与旧方案的差异（给开发者）

| 旧做法（11-07 设计稿、11-09 原型） | 现在的做法 | 原因 |
|---|---|---|
| 源满帧 → Biped 满帧参考 → 在参考上删键 | 先合法化到 Biped 自由度，再直接分部位排键 | 避免把 Biped 做不出的姿势写进去，也避免转换误差和减键误差叠加 |
| 以满帧参考为准，预算 1.5mm / 1.5° | 以观测为准，容差按源数据精度定在厘米级 | 满帧曲线本身就有厘米级误差 |
| 全身共享关键时间（11-09 版 70 个，其中 52 个不在整数帧） | 各部位独立定时间，全部在整数帧 | 键要落在有动作意义的位置，美术要选得中 |
| 优先修小腿可观测性（改关键点、重训 reader） | 暂缓；腿由 Biped IK 根据脚目标和重心算出 | 站立和行走时，膝盖主要由脚的位置和髋的高度决定 |
| 四段误差 A→B→C→D | 三个指标：相对观测的偏差、约束是否满足（脚漂移、膝盖弯曲、穿地）、编辑成本（键数、改一处牵连几个键） | 直接对应“像不像”“能不能用”“好不好改” |
| 在美术开着的 Max 窗口里跑脚本（send_editor） | 用 `3dsmaxbatch.exe` 无界面执行 | 不占用、不打扰美术的 Max 会话 |

**保留不变的原则**：原 rig 不动、planted IK 的写法（首键 sliding 新建锚点，后续 planted）、Max 实际回采验证、原有曲线保护、只在副本上操作、不覆盖已有输出。
