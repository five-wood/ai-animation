# 关键帧数据与网页接口约定

- **日期**：2026-11-11
- **用途**：网页（展示候选关键帧、让美术自定义打标）和后端抽取脚本共用的数据格式。关键帧的含义和类型定义见 [关键帧优先方案](关键帧优先方案_20261111.md) 第二节。
- **原则**：机器生成的候选和美术的标注分成两个文件，网页永远不改写候选文件。

## 一、文件位置

每个动画结果目录 `projects/<项目>/out/<结果名>/` 下：

| 文件 | 谁写 | 说明 |
|---|---|---|
| `keyframes_auto.json` | 抽取脚本 | 机器候选关键帧和判断依据的曲线。网页只读 |
| `keyframes_artist.json` | 网页保存接口 | 美术标注的最终关键帧。每次保存生成新版本 |
| `keyframes_artist_history/rev0001.json` … | 网页保存接口 | 历史版本，只增不删 |

视频：取结果目录 `summary.json` 里 `source_video` 的文件名，经 `/api/videos/<文件名>/file` 访问。找不到视频时界面要给出明确提示，不能白屏。

## 二、帧号约定

- 帧号是**视频自身帧率下的整数帧，从 0 开始**。`时间(秒) = 帧号 / fps`。
- ladingwu 是 193 帧、24fps。换算成 Max 的 30fps 在后续步骤里做，网页不涉及。
- 视频是双视角拼接（左半幅正面、右半幅侧面），1280×720。

## 三、`keyframes_auto.json`

```json
{
  "schema": "v2r.keyframes/1",
  "source_video": "ladingwu.mp4",
  "fps": 24.0,
  "frames": 193,
  "generated_at": "2026-11-11T18:30:00+08:00",
  "generator": "extract_keyframes.py 0.1",
  "params": { "min_gap_frames": 5, "amplitude_cm": 4.0 },
  "keyframes": [
    {
      "id": "k001",
      "frame": 0,
      "type": "start",
      "parts": ["body"],
      "reason": "片段第一帧",
      "confidence": 1.0,
      "detail": {}
    },
    {
      "id": "k004",
      "frame": 37,
      "type": "extreme",
      "parts": ["R_arm"],
      "reason": "右手离身体的距离到达峰值 38cm",
      "confidence": 0.82,
      "detail": { "peak_value": 38.1 }
    }
  ],
  "curves": {
    "body_speed":  [0.0, 1.2, "... 共 frames 个数"],
    "R_hand_speed": [],
    "L_hand_speed": [],
    "com_height":  [],
    "L_foot_contact": [1, 1, 0],
    "R_foot_contact": [1, 1, 1],
    "spin_yaw_deg": []
  },
  "curve_units": { "body_speed": "cm/s", "com_height": "cm", "spin_yaw_deg": "deg" }
}
```

字段规则：

- `id`：`k` 加三位序号，在同一个文件内唯一。
- `type`（单选，共 12 种）：

  | 值 | 中文名 | 含义 |
  |---|---|---|
  | `start` | 起始 | 片段第一帧 |
  | `end` | 结束 | 片段最后一帧 |
  | `contact` | 接触 | 脚着地 / 离地；`detail` 里有 `side`（`L` 或 `R`）和 `event`（`touch` 或 `lift`） |
  | `extreme` | 极值 | 动作到头、即将反向 |
  | `hold_start` | 停顿开始 | |
  | `hold_end` | 停顿结束 | |
  | `impact` | 发力点 | 击中、急停 |
  | `anticipation` | 预备 | 大动作前的反向蓄力 |
  | `rebound` | 回弹 | 到位后的小回弹 |
  | `technical` | 技术键 | 转身等需要保证插值方向的键 |
  | `breakdown` | 过渡键 | 决定两个关键姿势之间怎么走 |
  | `custom` | 自定义 | 只用于美术新增 |

- `parts`：数组，取值自 `body`、`head`、`L_arm`、`R_arm`、`L_foot`、`R_foot`、`ears`、`tail`。
- `confidence`：0 到 1。是机器对“这帧是关键帧”的把握，不是美术标注的质量。
- `curves` 里每条曲线长度都等于 `frames`。`*_contact` 为 0 或 1。缺失的帧用 `null`。曲线名以 `curve_labels` 为准，网页按名称取用，不要写死。0.2 版新增 `head_turn_deg`、`head_nod_deg`、`chest_turn_deg`、`chest_bend_deg`。
- 同一帧只能有一个关键帧。
- `keyframes` 只放结构键，不含 `breakdown`。过渡键在下面的 `breakdown_ladder` 里。

### 3.1 `breakdown_ladder`（0.2 版新增，可为 `null`）

结构键固定后，过渡键按“补上后插值偏差下降最多”的顺序逐个追加，形成一个排好名的列表。**取前 k 个就是 k 个过渡键的答案**，网页用它来做键数滑杆。算法见 [关键帧优先方案](关键帧优先方案_20261111.md) 第九节。

```json
"breakdown_ladder": {
  "generator": "breakdown_ladder.py 0.1",
  "frame_rate": 24.0,
  "structural_frames": [0, 11, 14, "…"],
  "suggested_count": 16,
  "suggestion_rule": "最少的过渡键数，使身体最大偏差 ≤ 4cm 且 p95 ≤ 2cm；达不到时取全部",
  "breakdowns": [
    { "rank": 1, "frame": 89, "between": [79, 95], "parts": ["body"], "worst_part": "Torso",
      "error_here_cm": 14.9, "interval_max_before_cm": 14.9, "interval_max_after_cm": 13.0,
      "clip_after": { "max_cm": 13.0, "p95_cm": 8.7, "mean_cm": 2.2 },
      "reason": "第 79–95 帧之间插值偏差最大处（Torso，14.9cm）；补上后这段最大偏差降到 13.0cm" }
  ],
  "error_curve": [ { "n": 0, "max_cm": 14.9, "p95_cm": 9.2, "mean_cm": 2.5, "spin": { "max_cm": 24.2, "p95_cm": 22.0, "mean_cm": 8.1 } } ],
  "spin_frames": [145, 171],
  "worst_intervals_before": [ { "between": [79, 95], "frames": 16, "max_cm": 14.9, "at": 89, "part": "Torso", "spin": false } ],
  "params": { "…": "…" }
}
```

- 帧号和 `keyframes` 一样，是视频帧。
- `error_curve[n]` 表示用前 n 个过渡键后的全身偏差，`n` 从 0 开始。`max_cm`、`p95_cm`、`mean_cm` 不含转圈段；转圈段的数值放在 `spin` 里。
- 网页显示建议：滑杆默认停在 `suggested_count`；显示前 k 个过渡键的帧号，与结构键用不同颜色区分；旁边显示 `error_curve[k]`。
- 计算失败时，这个字段为 `{"error": "…"}`，网页照常使用候选关键帧，不显示滑杆。
- 美术在网页里采纳的过渡键，用 `type: "breakdown"` 保存到 `keyframes_artist.json`，并记成 `origin: "ladder"`。这类条目的 `id` 是 `b` 加三位名次（例如 `b003`），`auto_id` 为 `null`，`auto_frame` 是阶梯里原来的帧号，`ladder_rank` 是它在阶梯里的名次，方便统计美术保留到了第几名。

## 四、`keyframes_artist.json`

```json
{
  "schema": "v2r.keyframes.artist/1",
  "revision": 3,
  "saved_at": "2026-11-11T20:10:00+08:00",
  "author": "美术A",
  "base_auto_sha256": "…",
  "reviewed": false,
  "notes": "转圈段想再加两个键",
  "keyframes": [
    { "id": "k001", "frame": 0,  "type": "start",   "note": "",           "origin": "auto",   "auto_id": "k001", "auto_frame": 0 },
    { "id": "k004", "frame": 39, "type": "extreme", "note": "再晚两帧才到头", "origin": "auto",   "auto_id": "k004", "auto_frame": 37 },
    { "id": "a001", "frame": 52, "type": "custom",  "note": "头先转过去",   "origin": "artist", "auto_id": null,   "auto_frame": null }
  ],
  "removed_auto_ids": ["k007"]
}
```

字段规则：

- `keyframes` 是**美术认定的最终关键帧全集**，包括保留的、挪动过的候选和新增的。
- `origin` 取值为 `auto`、`artist`、`ladder` 三种。
  - `auto`：必须有 `auto_id`，并且能在 `keyframes_auto.json` 里找到；`auto_frame` 是该候选原来的帧号，用来看出挪了几帧。
  - `ladder`：见 3.1，`ladder_rank` 为正整数，同一个名次只能出现一次。
  - `artist`：`auto_id`、`auto_frame` 都为 `null`。
- `removed_auto_ids`：美术明确删掉的候选。它用来区分“删掉了”和“没看过”。其中的 id 必须存在于候选文件，而且不能同时出现在 `keyframes` 的 `auto_id` 里。
- 新增关键帧的 `id` 由网页生成，格式为 `a` 加三位序号。
- `type` 可以改，取值同上。
- `reviewed`：美术勾选“已审核完毕”。
- `base_auto_sha256` 由服务端在保存时填入，是当时 `keyframes_auto.json` 文件内容的 SHA256。

## 五、接口

| 方法与路径 | 作用 |
|---|---|
| `GET /api/projects/{p}/out/{name}/keyframes` | 返回 `{auto, artist, video, fps, frames, revision}`。`auto`、`artist` 缺失时为 `null`；`video` 为 `{name, url}` 或 `null`；没有任何标注时 `revision` 为 0 |
| `PUT /api/projects/{p}/out/{name}/keyframes/artist` | 保存美术标注。请求体含 `author`、`base_revision`、`reviewed`、`notes`、`keyframes`、`removed_auto_ids`，其余字段由服务端补全 |

保存规则：

- 校验：帧号在 `[0, frames-1]` 内且为整数；同一帧只能有一个关键帧；`id` 不重复；`type` 在枚举内；关键帧数量不超过 500；`note` 不超过 500 字，`notes` 不超过 2000 字，`author` 不超过 40 字。
- 写入：先写临时文件再 `os.replace`；同时在 `keyframes_artist_history/` 下存一份 `rev{N:04d}.json`。
- 并发：`base_revision` 与当前版本不一致时返回 409，并带上当前版本，由前端提示后让用户决定。
- 路径：必须用 `safe_name` 和 `inside` 限制在结果目录内。

## 六、候选文件缺失时

网页仍然可用：美术可以直接在视频上从零打标，页面提示“尚未生成候选关键帧”。

## 七、网页实现状态（2026-11-12，仅本地，未部署）

**后端**

- [keyframes_store.py](../web/keyframes_store.py)：只用标准库实现读取、校验和保存，第四、五节的规则全部做到。
  - 校验失败返回 400，`detail` 是中文说明；`base_revision` 不一致返回 409，`detail` 为 `{message, current_revision, artist}`；候选文件正在重新生成、读不出来时返回 503。
  - `base_auto_sha256` 与读取所用的是同一份字节。
  - 历史版本只能新增：用 `os.link`，同名文件已存在时拒绝写入。
- [server.py](../web/server.py)：新增本约定第五节规定的 `GET` 和 `PUT` 两个接口，结果列表的每一项多一个 `has_keyframes: {auto, artist}`。
- GET 在约定之外还会返回三个字段：`auto_sha256`、`video_name`、`errors`。其中 `errors` 记录文件损坏的情况，例如 `{auto: "…不是有效的 JSON"}`。

**前端**

- [keyframes.js](../web/static/keyframes.js) 负责界面，[keyframes-core.js](../web/static/keyframes-core.js) 是不依赖页面的纯逻辑。入口有三个：
  - 侧栏的“关键帧”页；
  - 某个动画结果上的“关键帧标注 →”按钮；
  - 直接访问地址 `#<项目>/keyframes/<结果名>`。
- 页面功能：
  - **播放**：源视频可以看双视角，也可以只看正面或侧面。快捷键为：空格播放/暂停，←/→ 逐帧，Shift+←/→ 跳到上/下一个关键帧，K 在当前帧添加关键帧，Delete 删除当前帧的关键帧。另有 0.25 / 0.5 / 1 倍速和帧号输入框。
  - **时间轴**：按类型着色并带图例。已采纳的过渡键画得更细；建议过渡键用空心三角；已删除的候选用空心方块；挪过的键会从原位置到新位置画一条线。点击时间轴跳帧，拖动标注可以改帧。
  - **判断依据曲线**：可以勾选显示哪些曲线，脚的着地情况画成色带。
  - **关键帧预览条**：用隐藏的 `<video>` 加 canvas 截取缩略图，可视范围内的优先截取；每张卡片显示类型、来源、置信度、涉及部位、判断依据和备注；可以按来源筛选，在筛选里恢复已删除的候选、采纳单个建议过渡键。
  - **过渡键数量滑杆**：默认停在 `suggested_count`，旁边显示 `error_curve[k]` 和转圈段的数值，可以一键“采纳前 k 个”，同一帧已有关键帧的跳过并提示个数。
  - **保存**：
    - 作者名存在 localStorage 里，下次自动填上。
    - 有未保存的修改时会自动存为本机草稿，再打开这个结果时可以选择恢复。
    - 切换结果、切换项目或关闭页面前都会提醒。
    - 遇到 409，可以选“载入最新版本”，或者“基于最新版本覆盖保存”。
    - 可以导出 JSON。
- 没有候选文件、没有视频、过渡键阶梯计算失败、帧数未知时，页面都会明确提示，不会白屏。

**生成候选（11-12 新增并上线）**

- `GET .../keyframes` 多返回一个 `generation: {available, reason}`，表示这个结果能否在网页上生成候选。条件是：Biped 骨架、结果里有 `motion.npz` 和 `reading.npz`、服务器上有抽取脚本。
- `POST /api/jobs` 新增 `{cmd: "keyframes", args: {name, replace}}`。
  - 后端只接受结果名；
  - 已有候选时，必须带 `replace: true`，否则返回 409；
  - 不可生成时返回 400，`detail` 写明原因；
  - 同一项目已有任务在跑或在排队时，返回 409。
- 任务实际执行 `tools/max2026/run_keyframes.py <项目目录> <结果名>`，依次判断着地、抽取候选、计算过渡键阶梯。
  - 旧候选另存到 `keyframes_auto_history/<时间>_<sha12>.json`；
  - 新的 `keyframes_auto.json` 写入时原子替换；
  - `keyframes_artist.json` 不会被改动。
- 候选更新后，美术标注的 `base_auto_sha256` 与新候选不一致，页面打开时会自动转换（`keyframes-core.js` 的 `rebase`）：
  - 所有标注帧都保留；
  - 新候选里同 id、同原始帧的条目，仍记为候选来源（`origin=auto`）；
  - 其他条目改记为手动关键帧，id 改为 `a` 开头，`auto_id` 置为 null；
  - `removed_auto_ids` 里在新候选中已不存在的 id 会被忽略；
  - 页面提示转换结果并标记为未保存，由美术确认后保存。
